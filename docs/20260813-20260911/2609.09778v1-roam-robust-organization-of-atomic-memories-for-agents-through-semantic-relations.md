## 摘要
长期语言模型智能体在多次交互中依赖外部记忆。原子记忆尤其有用：其细粒度语义边界能够实现精确检索以及观测之间的直接比较。然而，累积的原子不可避免地会变得冗余、重叠或冲突。现有方法通常要求 LLM 管理器直接添加、更新、删除或重写记忆，将语义解释、存储决策和内容生成耦合在一个易出错的操作中。我们提出 ROAM，一个关系引导的框架，它在管理时利用原子性，同时允许在回答时使用更丰富的表示。ROAM 将传入-存储的原子对分类为独立、等价、方向性包含或冲突，然后将观测组织为活跃的 Primary 和支撑性的 Evidence 角色。随后，融合将互补细节和时间变化组合成紧凑的、可能非原子的视图。仅检索 Primary 视图用于回答，防止冗余或过时的原子独立参与竞争。在不同模型和评估设置中，ROAM 将回答准确率提升至多 29.8 个百分点。消融实验表明，不同关系带来互补收益，并且融合在角色组织之外带来一致增益。机制分析进一步发现，答案关键来源的召回率高出 15.6 个百分点，混杂 token 占比低 11.5 个百分点。ROAM 在不同管理器规模下保持稳健。

## Abstract
Long-term language-model agents rely on external memory across interactions. Atomic memories are particularly useful: their fine-grained semantic boundaries enable precise retrieval and direct comparison between observations. Yet accumulating atoms inevitably become redundant, overlapping, or conflicting. Existing methods often ask an LLM manager to add, update, delete, or rewrite memories directly, coupling semantic interpretation, storage decisions, and content generation in one error-prone operation. We introduce ROAM, a relation-guided framework that uses atomicity for management while allowing richer answer-time representations. ROAM classifies incoming--stored atom pairs as independent, equivalent, directionally subsuming, or conflicting, then organizes observations into active Primary and supporting Evidence roles. Fusion subsequently combines complementary details and temporal changes into compact, potentially non-atomic views. Only Primary views are retrieved for answering, preventing redundant or outdated atoms from competing independently. Across models and evaluation settings, ROAM improves answer accuracy by up to 29.8 percentage points. Ablations show complementary benefits from different relations and consistent gains from fusion beyond role organization. Mechanism analysis further finds 15.6-point higher answer-critical source recall and an 11.5-point lower confounder-token share. ROAM remains robust across manager scales.

## 1. 核心问题与研究动机

- **背景**：长期运行的 LLM 智能体需要跨会话持续积累用户偏好、情境与经验，但原始对话历史迅速超出工作上下文，因此普遍采用外部记忆库 + 查询时检索的架构。
- **原子记忆的价值**：将知识表示为细粒度、原子化的事实或结构化关系，可在极少 token 内保留显著信息，提供精确可寻址单元，并支持定向更新，已成为长期记忆系统的标准表示基础。
- **核心痛点**：原子化只规定了记忆的**粒度**，并未规定不断累积的原子事实应如何随时间共存。持续流入的观测必然带来语义重述、属性/空间细化、时间状态迁移，导致冗余、重叠、冲突。
  - 单纯追加 → 严重冗余与歧义；
  - 不加区分地删除/覆写 → 丢失追踪知识演化所需的历史上下文；
  - 未整理的记录会与答案关键证据争夺有限检索容量，直接损害下游回答质量。
- **现有方法的缺陷**：以 Mem0 为代表的“命令式直接操作”（ADD / UPDATE / DELETE / NONE）把**语义关系推断**、**物理存储变更映射**、**更新协调**耦合在一次黑盒复合决策中，导致操作后果不稳定、难以追溯历史。
- **论文主张**：应将**显式语义关系推断**与**确定性状态控制**解耦——即用“关系”作为模型判断与存储控制之间的接口。

## 2. 方法论

### 2.1 核心思想

- ROAM（Robust Organization of Atomic Memories）以**关系引导**替代黑盒改写：先推断新观测与既有记忆的细粒度语义关系，再由**固定策略**确定性地分配结构角色（Primary / Evidence），最后通过**融合**生成紧凑的“读取视图”供回答检索。
- 关键分离：
  - **原子文本（atomic text）**保持不可变，用于关系推断与溯源；
  - **读取视图（read view）**用于回答时检索，可以是紧凑的、非原子的；
  - 只有 Primary 视图参与回答检索，Evidence 保留但不独立竞争。

### 2.2 关键技术细节

- **三段式流水线**：Extraction → Management → Retrieval
  - `F_t = Extract(D_t)`，`S_t = Manage(S_{t-1}, F_t)`，`K_q = Retrieve(q, S_t; B)`
  - 原子观测定义为 `O_t = (a_t, τ_t, c_t)`，即自包含事实陈述、时间戳、来源上下文。
- **五类语义关系** `R = {IND, EQV, OSN, NSO, CON}`：
  - **IND（独立）**：两者可同时为真，互不蕴含；
  - **EQV（等价）**：真值条件相同、互相蕴含（仅措辞不同）；
  - **OSN（旧被新包含）**：新观测严格蕴含旧观测并增加特异性（如“住在 Cambridge, MA”⊨“住在 Massachusetts”）；
  - **NSO（新被旧包含）**：反向蕴含，新观测不增加特异性；
  - **CON（冲突）**：实体、属性、时间范围对齐后描述不相容状态；显式时间限定词在解决冲突时优先。
- **候选检索与关系预测**：
  - `C_t = ρ_k(a_t, P_{t-1})`：用原子文本从 Primary 集合中取 k 个最相关记忆；
  - `r_t(i) = Φ(a_t, a_i) ∈ R`：对每个有序对预测关系。
- **关系优先级**：`CON ≻ OSN ≻ EQV ≻ NSO ≻ IND`——先保护状态区分，其次偏好新增特异性，最后才合并冗余。
- **记忆记录结构**：`M_i = (a_i, v_i, τ_i, c_i, z_i)`，含原子文本、当前读取视图、时间戳、来源上下文、角色 `z_i`。
- **角色集合**：`P_t = {M_i : z_i = PRIMARY}`，`E_t = {M_i : z_i = EVIDENCE}`。
- **确定性角色更新规则**（表 1）：
  - `IND` → 新记忆作为新 Primary 插入；
  - `EQV` → 最早匹配的 Primary 存活，其余降为 Evidence（去除冗余）；
  - `OSN` → 新记忆成为 Primary，旧匹配降为 Evidence（保留新增特异性）；
  - `NSO` → 最早 Primary 存活，新记忆降为 Evidence；
  - `CON` → 新记忆成为当前 Primary，旧匹配降为 Evidence（构建时间历史）。
- **融合（Fusion）**：将 `{M*} ∪ D_t` 按观测时间排序，`v_{M*} ← Fuse(View(S_1),…,View(S_n); r*_t)`。融合只改读取视图：EQV 去冗余、OSN/NSO 保留兼容特异性、CON 记录时间状态变化。
- **流式算法（Algorithm 1）**：检索候选 → 若无候选则 `r* ← IND` → 否则收集关系标签并取最高优先级 → IND 则新建 Primary，否则取匹配集做角色更新、按时间排序融合视图。

### 2.3 回答时行为

- 检索仅在 Primary 读取视图上进行；Evidence 保留用于溯源与审计，但不占用回答时上下文竞争。
