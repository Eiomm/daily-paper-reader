## 摘要
开放网络未来事件预测要求智能体从噪声、冗余和不完整的证据中提炼可靠信号。现有的检索/记忆机制要么将检索到的信息直接馈送给智能体，要么依赖存储和复用先验信息等简单记忆功能来进行预测，难以胜任开放网络预测。我们提出在预测前将原始网络证据转化为结构化记忆，使智能体能够基于经过提炼、针对特定问题的证据进行推理，而非依赖含噪的检索结果。本文提出 ForeDreamer，一种用于管理开放网络证据记忆的自进化双智能体框架。ForeDreamer 将事实记忆（面向当前预测的特定问题证据状态）与经验记忆（跨预测回合累积的持久智能体经验）分离。它使用主智能体进行搜索和预测，并使用记忆处理子智能体借助专用工具将搜索结果转化为事实记忆。ForeDreamer 进一步通过两条路径演化经验记忆，同时改进预测决策和事实记忆构建。在 Prophet Arena 和 FutureX 上的实验证明了 ForeDreamer 的有效性。项目页面：https://zhongzero.github.io/ForeDreamer

## Abstract
Open-web future event prediction requires agents to distill reliable signals from noisy, redundant, and incomplete evidence. Existing retrieval/memory mechanisms directly feed retrieved information to agents or rely on simple memory functions such as storing and reusing prior information for prediction, leaving them insufficient for open-web forecasting. We propose to transform raw web evidence into structured memory before prediction, enabling agents to reason over distilled, question-specific evidence rather than noisy retrieval results. This paper presents ForeDreamer, a self-evolving dual-agent framework for managing memory over open-web evidence. ForeDreamer separates factual memory, a question-specific evidence state for the current forecast, from experiential memory, persistent agent experience accumulated across forecasting episodes. It uses a main agent for search and prediction, and a memory-processing subagent to convert search results into factual memory with dedicated tools. ForeDreamer further evolves experiential memory through two tracks, improving both forecasting decisions and factual-memory construction. Experiments on Prophet Arena and FutureX demonstrate the effectiveness of ForeDreamer. Project page: https://zhongzero.github.io/ForeDreamer

  - **RQ1**：智能体如何从噪声开放网络证据中做出可靠的未来事件预测？
  - **RQ2**：如何利用预测回合的反馈来演化经验记忆，同时改进事实记忆构建与预测决策？

## 2. 方法论

### 2.1 核心思想

- **双智能体分工**：
  - **主智能体（Main Agent）**：接收问题，参考经验库 B，规划搜索动作，整合事实记忆，输出最终预测与理由。
  - **记忆处理子智能体（Memory-Processing Subagent）**：接收原始搜索结果，在 **MemGuide**（工作流规范）与 **MemTools**（可执行操作集）指导下，将原始证据转化为事实记忆。
- **双记忆划分**：
  - **事实记忆**：查询条件化的证据制品，作用域限于当前预测问题，作为"原始证据—最终预测"之间的显式接口。
  - **经验记忆**：跨预测回合持久累积，包含文本型预测经验与过程型证据加工经验。

### 2.2 任务形式化与推理流程

- 每个实例由问题 $q$ 与时间截断 $\tau_q$ 组成，证据空间记为 $E_{\le \tau_q}$，输出预测 $\hat{y}$（概率分布或离散标签）。
- **多轮搜索-推理循环**（预算 T 轮）：
  1. 第 $t$ 轮发出查询 $s_t$，执行截断感知检索：$R_t = \text{Search}(s_t, E_{\le \tau_q})$；
  2. 每条结果 $r_{t,k}$ 归一化后写入 artifact workspace；
  3. 子智能体按所选 MemGuide/MemTools 加工：$m_{t,k} = P_{g,T_g}(r_{t,k}, q)$，并返回 $M_t$；
  4. 累积事实记忆 $M_{1:K} = \bigcup_{t=1}^{K} M_t$；
  5. 最后一轮禁止调用工具，直接作答：$\hat{y}, \rho = A(q, B, M_{1:K})$。
- **可审计性**：每条事实记忆可回溯到对应检索条目；多阶段加工的中间产物保留在同一条目级 workspace 中。

### 2.3 双轨经验进化（Dual-Track Self-Evolution）

在一个小的进化-验证池 $D_{evo}$ 上进行，验证结果同时充当候选准入闸门。

- **轨道一：文本型预测经验进化**
  - 经验库 $B^{(v)} = \{e_i\}_{i=1}^{n_v}$；采样 $D_{evo}$ 中的样例跑 rollout，由 editor 提出 ADD / MODIFY / REMOVE 操作得到候选库 $\tilde{B} = o(B^{(v)})$。
  - **仅当验证分数提升时接受**：$B^{(v+1)} = \tilde{B}$ 若 $\tilde{B} \succ B^{(v)}$，否则保持 $B^{(v)}$。
  - 该轨道改进搜索规划、证据整合与预测校准。

- **轨道二：过程型证据加工经验进化**
  - 用 **MemGuide 树** $G=(V,E)$ 表示过程经验，节点为 MemGuide，边记录来源（provenance）。
  - **父节点选择**采用"验证排名 Zipf 采样"：若 $g_i$ 在 N 个有效节点中排名 $r_i$，则 $p(g_i) = \frac{1/r_i}{\sum_j 1/r_j}$，兼顾强者优先与非零探索概率。
  - 由 critic 从 rollout 推导设计需求 $d$，生成候选 $(\tilde{g}, \tilde{T})$；若 $\text{Valid}(\tilde{g}; D_{evo})=1$（所有验证样例运行成功），则 $V \leftarrow V \cup \{\tilde{g}\}$，$E \leftarrow E \cup \{(g_i, \tilde{g})\}$。

- **两个优化（针对 vanilla 进化的诊断性问题）**：
  - **组合式工具复用（Compositional Tool Reuse）**：
    - *观察*：vanilla FutureX 设置下 201 个生成的 MemTool 在 token-Jaccard 阈值 $\tau=0.5$ 时塌缩为 98 个簇（簇比例 48.8%），存在大量近重复实现。
    - *方法*：从设计需求出发，从活跃工具集中选出兼容子集 $T_{reuse} = R(d, T_{active})$，候选 MemGuide 重新生成但复用所选工具，仅为未覆盖操作生成新工具，即 $\tilde{T} = T_{reuse} \cup T_{new}$，仍过同一验证闸门。
  - **多样性引导探索（Diversity-Guided Exploration）**：
    - *观察*：vanilla 进化在 FutureX 上产出的 10 个 MemGuide **全部落入同一"工具编排型"流水线原型**，说明只在一个局部族系内精化。
    - *方法*：增加一条**不需要新 rollout** 的探索路径，通过 MemGuide 类别摘要与代表指南生成非局部变体的候选；由调度器在探索与 rollout 扩展间交替。类别判定关注工作流意图、阶段结构、状态转移、中间制品使用、工具组成与职责划分，而非命名/措辞差异。

### 2.4 工程与安全细节

- **MemGuide 与 MemTool 接口分离**：MemGuide 只定义目标与允许调用的工具（不直接执行 I/O）；MemTool 实现有界操作（读原始证据、抽取、构建中间表示、校验、写最终事实记忆）。
- **候选校验**：先检查 MemGuide 字段完整性、所有引用工具可用；再校验 MemTool 语法、接口一致性、与 tool-calling schema 的兼容性；guide 与 tools 作为**互一致的整体**一并发布，避免部分有效更新污染状态。
- **受控工具执行**：主智能体只能访问公开的 search-and-process 接口；子智能体只能调用当前 MemGuide 白名单内的 MemTool；工具运行于 `bwrap` 沙箱，禁止网络访问，读写仅限 `item_dir`，每次调用有预算上限。
- **候选选择**：FutureX 按 accuracy 排序，Prophet Arena 按 Brier 排序；仅验证合格的 MemGuide 节点参与排序。

    - 进化池与测试集同分布采样，但进化池仅 5/20 例，且未报告多次随机种子下的方差或置信区间；
    - Prophet Arena 与 FutureX 的评测期均落在骨干模型训练截止之后，虽有助于防污染，但也意味着模型对近期事件的知识近乎为零，结果可能对检索质量高度敏感；
    - Sports 子集抽样 400 例的原因与抽样方式（是否随机、是否分层）未充分说明；
    - 未报告统计显著性检验（如配对检验、bootstrap 置信区间），部分类别上的差距可能落入噪声范围。

## 6. 主要结果与结论方向

> 说明：以下为论文所报告的结论方向，具体数值需参见原文 Table 1–6 与附录表格。

- **主结果（Table 1 / Table 2）**：ForeDreamer 在 Prophet Arena（Brier score，越低越好）与 FutureX（Accuracy，越高越好）上，在两个骨干模型下均取得相对所有 baseline 的最佳表现。对比对象包括 Full Text 长上下文直灌、通用 RAG、以及六类智能体记忆系统（HippoRAG 2、Mem0、MemoryOS、A-MEM、LightMem、LangMem）。由于所有方法共享同一检索模块与同一批证据，性能差异主要归因于"证据加工与记忆组织"方式，而非检索能力。
- **类别层面（Prophet Arena 8 类）**：论文按类别独立进化并逐类报告，显示增益并非集中于单一类别；Sports 使用 400 例子集以避免类别样本失衡主导整体指标。辅助的市场回报指标（Table S3）用于交叉验证 Brier score 的改进是否具有实际决策价值。
- **双轨消融（Table 3、S4–S6）**：分别移除 MemGuide&MemTool 的过程进化与 Experience Bank 的声明式进化，两种移除均导致性能下降，且同时移除时退化更明显，说明**两条轨道贡献互补**——一条改善"如何加工证据"，另一条改善"如何规划搜索与校准预测"。该结论在 Qwen3.5-Flash、GPT-5.4-Nano 与 GPT-5-Nano 三个骨干上方向一致。
- **过程进化优化消融（Table 4、S7）**：
  - 移除**组合式工具复用**后性能下降，印证 vanilla 进化中近重复工具膨胀（201 → 98 簇，48.8%）确实造成冗余与不一致；
  - 移除**多样性引导探索**后性能下降，且 MemGuide 原型分布更集中于单一"工具编排型"流水线，说明探索路径缓解了局部族系过拟合；
  - 两者同时移除时退化最大。
- **鲁棒性（Table 5、S8）**：在交互轮数 3/4、Firecrawl 搜索、Top-2/6/8 检索结果、60K/90K 搜索上下文共 8 种配置下，方法保持相对优势，说明其增益不依赖于某一特定的检索-交互超参组合。
- **数据泄漏检查（Table 6、S9、S10）**：No Information（完全无搜索）条件显著劣于 Full Text 与 ForeDreamer，表明基准确实需要外部检索、答案并非来自参数记忆；同时 Full Text 明显弱于 ForeDreamer，说明"检索到证据"与"把证据加工成可预测的事实基础"之间存在实质性差距——这正是论文的核心论点。
- **机制分析**：
  - 工具相似度在 token-Jaccard / normalized sequence / AST sequence 三种度量、3 个阈值（0.4/0.5/0.6）、2 个数据集下一致显示 vanilla 进化产生大量近似重复工具，支持组合式复用的必要性（Table S11、Figure S1/S2）；
  - MemGuide 原型分布对比（Figure 5、7、S3）显示多样性引导探索后，10 个 FutureX MemGuide 从"全部落入同一原型"扩展为覆盖多个原型类别。

## 7. 论文的核心贡献与定位

1. **问题重构**：把开放网络未来事件预测中的"记忆"重新定义为**预测前的证据加工过程**，而非被动的存储—检索—复用，明确指出通用记忆系统在此任务上的任务错配。
2. **架构贡献**：提出事实记忆 / 经验记忆的双层划分，以及主智能体 + 记忆处理子智能体的双智能体分工，使"原始证据 → 事实记忆 → 预测"形成显式、可审计的接口。
3. **进化机制贡献**：提出双轨自进化（文本型预测经验 + 过程型证据加工经验），并针对 vanilla 进化的两个病理现象（工具近重复膨胀、MemGuide 原型塌缩）分别给出组合式工具复用与多样性引导探索两项修正。
4. **实证贡献**：在两个 live 预测基准（Prophet Arena、FutureX）上，跨多个骨干模型、多类 baseline、多组消融与鲁棒性配置，验证了方法的有效性。

## 8. 局限性与可改进方向

- **算力与成本完全未报告**：60 次进化迭代 × 多次 rollout × 代码生成与沙箱执行的开销不可评估，难以判断方法的实际部署成本。
- **进化池过小**：Prophet Arena 每类 5 例、FutureX 20 例，反馈信号稀疏，可能限制进化上限，也使结果方差缺乏刻画。
- **候选选择协议存在偏差风险**：以验证性能排序、保留 top-5、报告**最佳测试表现**，本质上是测试集上的模型选择，理想做法应报告 top-1 或使用独立留出集。
- **缺少显著性检验与多次种子结果**。
- **工具生成的可靠性与安全性**：LLM 生成的 MemTool 虽经语法/接口校验与 `bwrap` 沙箱隔离，但其语义正确性、潜在偏差、以及沙箱逃逸面仍值得更系统的评估。
- **基准时效性**：依赖 live 基准是优点也是局限——结果难以被后续研究者精确复现（问题集随结算状态漂移）。
- **可扩展方向**：把进化池扩大到更大规模、引入更严格的统计评估协议、将事实记忆的加工范式迁移到其他时效敏感任务（如金融、政策跟踪），以及探索跨类别经验共享而非按类别独立进化。

## 9. 总体评价

ForeDreamer 的贡献主要在于**概念澄清**与**工程化的自进化闭环**：它把"开放网络预测"这一任务的瓶颈从"检索到什么"重新定位到"如何把检索结果加工成可预测的事实基础"，并用事实/经验双记忆、双智能体分工、双轨进化把这一主张落地为可运行的系统。实验在基准选择（两个 live 基准）、防污染设计（时间截断检索 + 训练截止较早的额外骨干）与消融覆盖度上较为扎实，且所有 baseline 共享同一检索证据，比较口径相对公平。

其主要短板在于**评估协议的严谨性**（小进化池、测试集上的最佳候选选择、缺少显著性检验）与**资源透明度的缺失**。因此，论文的性能增益方向可信，但增益的精确幅度与稳定性仍需更严格的协议来确认。对于后续工作，最有价值的参考点或许是它提出的"记忆即加工"视角，以及工具近重复膨胀与原型塌缩这两类可复用的诊断性观察。
