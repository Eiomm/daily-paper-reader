## 摘要
大型语言模型（LLM）智能体在复杂的长时程任务上往往表现不佳，因为其上下文会随时间推移变得越来越杂乱。随着交互不断累积，详细的执行轨迹和中间输出会主导上下文，使模型难以保留并使用高层规划信息。现有大多数方法通过对单一扁平上下文进行压缩或检索来解决这一问题，但这并未清晰区分不同类型的上下文信息，且常常导致推理能力下降。为应对这一挑战，我们提出 HyMem，一个显式地将智能体上下文分离为不同功能层的分层框架。HyMem 按功能组织上下文，将高层规划与执行及复杂分析分离。其隔离推理模块可处理复杂子任务，而不会将中间推理轨迹添加到持久的规划上下文中；其记忆管理模块通过结构化摘要，在上下文刷新过程中保留任务进展。这些组件减少了冗余上下文累积，保留了任务关键信息，并支持在有限上下文窗口内进行连贯的长时程推理。在 GAIA 和 Browsecomp-plus 上的实验表明，使用 DeepSeek-V4 时，HyMem 的平均 Pass@1 分数分别达到 66.7% 和 61.3%，分别比最强基线高出 6.1 和 4.7 个百分点。进一步分析表明，HyMem 能有效控制推理上下文的增长，使模型在复杂的长时程任务中保持专注和准确。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

# HyMem 论文中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题：长时程智能体的“上下文稀释”（context dilution）**。LLM 智能体在复杂长时程任务中，随着交互不断累积，原始工具输出、浏览日志、重试、格式噪声等**执行层轨迹（execution traces）** 快速增长，而**规划层信号（goals、verified facts、constraints、unresolved sub-goals）** 稀疏且增长缓慢，导致任务关键信息被冗余历史“淹没”。
- **结构错配**：长时程任务天然包含两类信息流——需要稳定连续的高层战略规划，与噪声大、瞬态的低层执行轨迹。但标准扁平上下文架构（如 ReAct）将二者交织在同一序列中，使智能体“迷失在工具使用细节里，忘记原始目标”。
- **现有方法的不足**：上下文压缩（如 Summary、MemAgent、MEM1）与外部记忆检索（如 A-MEM、Mem0、MemOS）通常作用于**已经混合的扁平序列**，难以区分推理信号与执行噪声；压缩易丢失关键推理链，检索难以保留时序逻辑与层级区分。因此它们只解决“上下文长度”这一症状，未解决“不同信息被混在一起”这一根因。
- **论文主张**：应从**信息隔离（information isolation）** 入手，按功能将上下文分层管理，从源头上阻止冗余执行信息进入决策空间。

## 2. 方法论：HyMem 框架

### 2.1 核心思想
- **类型化上下文隔离（typed context isolation）**：将规划、工具执行、隔离子任务推理、记忆整合维护在**相互独立的上下文空间**中，只有**schema 约束的消息**可以跨越边界；底层上下文在返回结构化结果后即被丢弃。
- **训练无关（training-free）**：作为推理时控制器包裹冻结的基础 LLM，即插即用。

### 2.2 问题形式化
- 传统 ReAct 维护扁平上下文：`Ct = (P, q, (a1,o1), ..., (at,ot))`。
- 用两个功能投影描述异构信息：`Zt = πZ(Ct)`（规划相关信息）与 `Xt = πX(Ct)`（执行层轨迹）。
- 定义**信息密度** `ρt = |Zt| / |Ct|`；长时程中 `|Xt|` 增长快于 `|Zt|`，导致 ρt 下降，即上下文稀释。
- 期望的信息边界：`C(p)_{t+1} = U(C(p)_t, Rt)`，且条件互信息 `I(C(p)_{t+1}; Xt | Rt) ≈ 0`，即规划器更新只依赖结构化返回 Rt，与原始执行轨迹近似独立（由接口设计强制，而非可微目标）。

### 2.3 四个组件与关键流程
- **Planner Layer（规划层，唯一贯穿全任务）**
  - 上下文：`C(p)_t = (P(p), q, Mepi_t, Mwm_t, Mtool_t, H(p)_t)`。
  - 每步只发出一个动作：`A = {⟨TASK⟩(d), ⟨ISO REASON⟩(d), ⟨FOLD⟩, ⟨ANSWER⟩(ŷ)}`。
- **Executor Layer（执行层，按需实例化）**
  - 初始上下文：`C(e)_{t,0} = (P(e), d, Mtool_t)`；执行有界工具调用循环，得到原始观测。
  - 通过**相关性条件蒸馏算子** `õ_{t,j} = φ(o_{t,j} | d)` 去除导航文本、重复段落、格式噪声、无关片段与工具错误模板，保留实体、日期、数值、来源、证据片段与候选答案。
  - 合成结构化返回：`R(e)_t = ⟨RESULTS⟩[findings, evidence, sources, status, gaps]⟨/RESULTS⟩`，仅该返回被追加到规划器，执行上下文与原始观测被丢弃。
- **Isolated Reasoning Module（隔离推理模块）**
  - 面向多跳分析、假设检验、冲突证据调和等复杂子任务；上下文为 `C(iso)_{t,0} = (P(iso), d, Mepi_t, Mwm_t, Mtool_t, τ(H(p)_t))`，其中 τ 选取近期规划状态以锚定子任务。
  - 可调用执行器获取额外证据，但**中间推理轨迹保持私有**；返回 `R(iso)_t = ⟨RETURN⟩[conclusion, supporting facts, sources, confidence κ, assumptions]⟨/RETURN⟩`，κ∈[0,1] 为自估置信度，之后隔离上下文被丢弃。
- **Memory Management（结构化记忆）**
  - 维护三类可重写记忆：`Mt = {Mepi_t, Mwm_t, Mtool_t}`——**episode memory**（已完成里程碑、已验证事实、重要决策）、**working memory**（当前目标、未解缺口、下一步计划）、**tool memory**（有效工具使用模式、失败查询、工具特定注意事项）。
  - **折叠算子**：`Mt+1 = Φ(H(p)_t, H(e)_{≤t}, H(iso)_{≤t}, Mt)`。
  - **非对称记忆注入**：Planner 与 Isolated 接收三类记忆；Executor 仅接收工具记忆（且注入规划器的是紧凑过程性摘要，而非原始工具日志）。
- **折叠触发条件**（显式 `⟨FOLD⟩` 或满足任一）：规划上下文 token 利用率 > 0.99、执行器调用次数 ≥ 5、连续失败 ≥ 3、规划轮次 ≥ 8、工具调用 ≥ 10。
- **上下文边界效果**：原始观测只进入执行器、中间推理 token 只进入隔离上下文，均在返回后被删除；规划器仅通过有界类型化返回与重写记忆增长，从执行全程限制“什么信息可以进入决策上下文”，而非事后压缩扁平轨迹。
