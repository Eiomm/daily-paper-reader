## 摘要
函数调用是智能体大语言模型（LLM）的核心能力。现有研究主要关注通过微调、强化学习（RL）和多智能体框架来提升LLM的函数调用准确率，尤其是针对原生函数调用LLM。本工作表明，LLM在指令遵循语境（即标准用户-助手交互）中比在工具调用语境中能获得更高的函数调用准确率。我们提出指令遵循式函数调用（IFFC），一种新颖框架，将函数调用逻辑与主LLM解耦，并将其交由一个在指令遵循范式下运行的专用较小模型处理。我们的方法持续优于原生函数调用（NFC）和基于提示的函数调用（PFC）基线，在面向推理的LLM上提升尤为显著。此外，我们证明IFFC在激进量化下仍保持稳健性能，从而实现高效的端侧部署且无显著精度下降。本工作为边缘计算场景中可靠、资源高效的函数调用建立了一种新范式。

## Abstract
Function calling represents the core capability of agentic large language models (LLMs). Existing research has focused on enhancing LLMs function-calling accuracy through fine-tuning, reinforcement learning (RL), and multi-agent frameworks, particularly for native function-calling LLMs. This work demonstrates that LLMs achieve superior accuracy in function calling in instruction-following contexts (i.e., standard user-assistant interactions) rather than a tool calling context. We introduce Instruction-Followed Function Calling (IFFC), a novel framework that decouples function-calling logic from the primary LLM and delegates it to a dedicated smaller model operating within the instruction-following paradigm. Our method consistently outperforms both native function calling (NFC) and prompt-based function calling (PFC) baselines, with particularly strong gains on reasoning-oriented LLMs. Furthermore, we demonstrate that IFFC maintains robust performance under aggressive quantization, enabling efficient on-device deployment without significant accuracy degradation. This work establishes a new paradigm for reliable, resource-efficient function calling in edge-computing scenarios.

# 论文总结：《Small Reasoning Models are Instruction Followers in Function Calling》

## 1. 核心问题与研究背景

- **背景**：函数调用（Function Calling）是智能体大模型（Agentic LLM）的核心能力，使模型能够选择工具、生成参数并执行动作。当前主流做法是**原生函数调用（NFC）**，即依赖 `<tool_call>` 等专用控制 token 与严格 JSON schema；对小型语言模型（SLM，0.5B–15B）而言，这套范式带来格式错误、schema 校验失败与多步推理脆弱等问题。
- **核心洞察/质疑**：作者挑战"必须使用 NFC"的既有假设，认为语言模型（尤其是推理型模型）的架构强项在于**遵循自然语言指令**，而非操纵刚性工具定义。因此，模型在标准"用户-助手"指令遵循语境中的函数调用准确率，应高于专用工具调用语境。
- **整体含义**：论文提出 **IFFC（Instruction-Followed Function Calling）**，把函数调用逻辑从主问答 LLM 中解耦，交给专用的小型推理模型（SRM）在指令遵循范式下执行，从而在边缘计算场景实现可靠、低资源、隐私友好的智能体部署。

## 2. 方法论

### 2.1 核心思想：两阶段解耦

- **阶段一（意图评估与工具路由）**：由专用 SRM（0.5B–15B）接收用户查询，判断是否需要外部工具/上下文，并在需要时生成函数调用与参数。
- **阶段二（最终回答合成）**：主 QA LLM 只接收"原始查询 +（若需）工具返回结果"，专注生成面向用户的自然语言回复。
- **阶段三（状态分离与 token 优化）**：主 LLM 记忆更新为 `{Q, R}`；SRM 记忆仅更新为 `{Q, O_SRM}`，**刻意排除主模型的长回复 R**，从而抑制 SRM 输入上下文窗口在多轮对话中的膨胀。

### 2.2 关键设计：IFFC vs. NFC vs. PFC

- **NFC**：使用非对话式专用 token 声明与调用工具，对格式错误敏感、易脆弱。
- **PFC（基于提示的函数调用）**：将工具序列化进 system prompt，在标准 assistant 角色中输出调用，适合无原生工具调用能力的模型（如 Gemma-3）。
- **IFFC 与 PFC 的两点关键差异**：
  1. **解耦架构**：标准 PFC 把工具定义喂给主对话模型；IFFC 完全交给独立 SRM，实现上下文隔离。
  2. **定制化格式**：IFFC 不强求通用 JSON 格式，而是采用针对 SRM 推理能力优化的专用输出格式。
- **算法流程（Algorithm 1）**：
  1. 构造 SRM 输入 `X_SRM = FormatPrompt(P_SRM, F, Q, H_SRM)`，由 SRM 以 PFC 方式生成 `O_SRM`；
  2. 若 `O_SRM` 触发函数 `f ∈ F` 及参数 `θ`，执行 `C ← Execute(f, θ)`，构造 `Q_enriched = Combine(Q, C)`；否则 `Q_enriched = Q`；
  3. 主 LLM 生成 `R ← LLM_Main(FormatPrompt(P_Main, Q_enriched, H_Main))`；
  4. 更新 `H_Main ← H_Main ∪ {Q, R}`，`H_SRM ← H_SRM ∪ {Q, O_SRM}`，返回 R。
- **提示工程细节（附录 A.3）**：针对参数格式幻觉，在系统提示中显式要求"使用与函数定义示例完全相同的参数值格式"（例如要求输出 `"Paris, France"` 而非 `"Paris"`），显著减少 schema 校验错误。附录 B 给出完整可复现的 IFFC 系统提示。
- **附加机制**：SRM 采用 **ReAct（Reason-Action）** 推理轨迹；混合推理模型可开关"Thinking"模式。

## 6. 主要结论与发现

- **指令遵循优于原生工具调用**：在 Qwen-3 全系（0.6B–8B）与 Phi-4 Mini 上，IFFC 一致优于 NFC。Phi-4 Mini 在 Live 上从 NFC 的约 30% 提升至 IFFC 的 44.3%；Qwen-3 4B（Think）达到 Live 86.7% / Non-Live 94.1%。
- **PFC 在高复杂度场景崩溃，IFFC 稳健**：Gemma-3 4B 使用 PFC 在 "Parallel Multiple" 上准确率跌至近 0%（Live 29.2%），而 IFFC 保持 54.2%；Gemma-3 12B 的 IFFC 在该类达到 79.2%。
- **小模型可匹敌专有巨型模型**：Non-Live 上 Qwen-3 4B（IFFC）在 Simple 达 96.0%、Multiple 达 97.5%，超过 Claude 4.5 Sonnet（72.6% / 95.5%）与 GPT-5.2（72.9% / 88.0%）；Parallel Multiple 达 90.5%，接近 Claude 4.5（92.0%），远高于 Gemini 2.5 Pro（40.0%）。
- **推理（Thinking）模式增益显著，尤其对小模型**：Qwen-3 0.6B 在 Live 上从 22.9%（No-Think）跃升至 57.7%（Think）；4B 从 74.6% 提升至 86.7%。
- **推理模型对量化异常鲁棒**：Qwen-3 4B（Think）在 Q4KM 下保持 93.5%（FP16 为 94.1%），8B（Think）甚至微升至 94.4%；而标准模型严重退化——Gemma-3 1B 从 23.9% 降至 8.7%，Qwen-3 0.6B（No-Think）从 62.3% 跌至 16.8%。作者认为"推理轨迹"起到误差纠正作用，可补偿权重精度损失。
