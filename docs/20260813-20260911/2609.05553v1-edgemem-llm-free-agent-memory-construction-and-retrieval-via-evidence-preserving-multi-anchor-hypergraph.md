## 摘要
智能体记忆使LLM智能体在回答新查询时能够利用先前的交互。现有方法通常将交互历史压缩为摘要或其他由LLM生成的表示。反复生成会增加成本，并可能在系统尚不清楚未来查询需要什么之前就丢弃承载答案的细节。我们提出EdgeMem，一种围绕简单原则构建的智能体记忆方法：保留原始交互轮次，并通过互补的内容、时间和情节线索对其进行组织。EdgeMem通过轻量级本地处理构建的多锚点超图来实现这一原则。检索直接返回源证据，并将LLM的使用保留给最终答案生成，从而将多会话历史的结构化访问与对原始对话的忠实保留相结合。在LoCoMo和LongMemEval-S上的实验显示出强大的检索能力和基于记忆的问答表现；在LoCoMo上，EdgeMem在共享提示下于七个复现系统中取得最高的严格评判分数（61.01对58.70），而其构建与检索均无需调用生成式LLM。总体而言，EdgeMem表明，保留并组织源证据能够为智能体记忆提供有效且高效的基础，而无需生成式记忆管理。

## Abstract
Agent memory allows LLM agents to use earlier interactions when answering new queries. Existing methods often compress interaction histories into summaries or other LLM-generated representations. Repeated generation adds cost and can discard answer-bearing details before the system knows what a future query will require. We propose EdgeMem, an agent-memory method built around a simple principle: preserve original interaction turns and organize them through complementary content, temporal, and episodic cues. EdgeMem realizes this principle with a multi-anchor hypergraph constructed by lightweight local processing. Retrieval directly returns source evidence and reserves LLM use for final answer generation, combining structured access to multi-session histories with faithful retention of the original conversation. Experiments on LoCoMo and LongMemEval-S show strong retrieval and memory-grounded question answering; on LoCoMo, EdgeMem achieves the highest strict-judge score among seven reproduced systems under a shared prompt (61.01 versus 58.70), while construction and retrieval require no generative-LLM calls. Overall, EdgeMem shows that preserving and organizing source evidence provides an effective and efficient foundation for agent memory without generative memory management.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体需要"记忆"来在回答新问题时利用早先的多会话交互历史。随着历史增长，全量喂入上下文既昂贵又可能超出窗口，因此主流做法是把历史外置存储、只检索少量证据。
- **现有主流范式的两大问题**（对应 Figure 1）：
  - **成本问题**：在记忆的构建、更新、检索全生命周期中反复调用 LLM（生成摘要、抽取记忆单元、构建层级存储、查询时导航/过滤），token 消耗随历史增长而剧增。论文实测显示，在 LoCoMo 规模下，**每一个主流 baseline 仅"记忆构建"一项就已超过原始历史本身的 token 量**（如 A-Mem 11.77M、MemoryOS 4.49M）。
  - **保真度问题**：LLM 生成的摘要/记忆单元会遗漏或扭曲原始轮次中的细节。一旦承载答案的细节在写入阶段丢失，后续任何检索都无法恢复——这是一个**原则上不可逆**的失败。
- **核心主张**：记忆应**原样保留原始交互轮次**，仅用内容、时间、情节三类互补线索对其组织；生成式 LLM 只保留给"最终答案生成"这一环。作者从情景记忆（episodic memory）研究获得灵感：一次经历可通过"讨论什么、何时发生、属于哪个事件"三条路径被回忆。
- **整体含义**：EdgeMem 证明"保留并组织源证据"本身即可构成有效且高效的智能体记忆基础，无需生成式记忆管理，且天然带来可溯源性与更可靠的"拒绝回答"能力。

## 2. 方法论

### 2.1 形式化设定

- 交互历史表示为有序轮次序列 `T = (t_1, ..., t_N)`；每个轮次 `t = (x_t, u_t, s(t), i(t), τ_t)`，分别为原文、说话人、原生会话、会话内位置、会话日期。
- 原生会话即一个 **episode**；记忆系统被定义为三元组 `(Φ, Ψ, F)`：构建 `Φ(T) → M`，检索 `Ψ(q, M) → P(q)`，阅读器 `F(q, P(q)) → 回答`。证据包上限为 `κ` 个轮次、`B` 个渲染 token。
- **设计不变式**：`tok_LLM(Φ) = tok_LLM(Ψ) = 0`，即构建与检索零生成式 LLM 调用。

### 2.2 轻量本地标注（Anchor Keys）

- 使用本地 NLP 工具（spaCy 3.8.11 + `en_core_web_sm`、rank_bm25 0.2.2、dateparser 1.2.2）对每个轮次抽取：
  - **实体集 `E_t`**：人名、组织、地缘政治实体/地点、国籍/群体、命名事件、产品、日期时间等。
  - **关键词集 `K_t`**：去停用词、去限定词与所有格后的词形还原内容词。
  - **会话日期 `τ_t`** 直接取自转录元数据。
- 原始文本 `x_t` **逐字保留**，与 `u_t, s(t), i(t), τ_t, E_t, K_t` 一同存储。

### 2.3 多锚点超图构建

- 超图 `H = (V, E)`，顶点为源轮次 `V = {t_1, ..., t_N}`，三类带类型超边 `E = E_time ⊔ E_co ⊔ E_epi`：
  - **Time Sub-Hypergraph**：`e^time_m = {t | τ_t ∈ m}`，按日历月 `m` 分组，支持日期跨度访问。
  - **Co-occurrence Sub-Hypergraph**：`e^co_w = {t | w ∈ E_t ∪ K_t}`，每个实体/内容键 `w` 形成一个 hub，其文档频率 `df(w)` 为关联轮次数，支持跨会话的共享键访问。
  - **Episode Sub-Hypergraph**：`e^epi_s = T_s`，每个原生会话为一个 episode，保留轮次顺序，提供会话级上下文。
- 每个源轮次记录**只存一份**，即使它属于多个 hub；构建是**追加式（append-only）**的，三类访问结构同步增长。

### 2.4 检索流程（确定性、预算感知）

- **查询线索抽取**：本地标注产生 `E_q`、`K_q`；`A_q = E_q ∪ K_q` 作为实体线索，分词后作为词汇线索。两个 BM25 索引分别对原始轮次文本 `x_t` 与拼接的 episode 文本 `X_s` 打分，得到 `r_turn` 与 `r_epi`；受保护的解析器返回日期跨度 `D_q` 或 `⊥`。
- **Episode 通道（证据核心）**：`ρ(t) = λ·r̂_turn(q, x_t) + (1−λ)·r̂_epi(q, X_{s(t)})`（各自 max 归一化，全零则置零）。按 `ρ` 排序，混合全局排名与不同 episode 的代表，对枚举型问题用固定词汇触发提高 episode 覆盖率；每个种子读出其紧邻前驱与后继，稳定去重后取 `k` 个轮次。
- **Co-occurrence 通道**：只激活文档频率落在**稀有键带** `[δ_min, δ_max]` 的查询键，选出与这些 hub 相连且尚未被 Episode 通道选中的轮次：`R_co(q) = {w ∈ A_q | δ_min ≤ df(w) ≤ δ_max}`，`C_co(q)` 取其 top-`ρ` 的未见轮次，填满预留的 co-occurrence 预算。
- **Time 通道**：**日期跨度门控**仅在 `D_q` 含明确月份与四位年份时开启（有日精度则保留）。月份 hub 定位跨度内 episode，固定加宽规则额外纳入跨度后第一个 episode；候选为 episode 起始轮与池中最高 `ρ` 轮次，最多 `b_time` 个。门关闭时通道为空。
- **融合与证据包**：`b_time = 1[D_q ≠ ⊥]·n_time`，`b_co = min(n_co, max(0, κ − k − b_time))`，`P(q) = dedup(C^k_epi(q) ‖ C^{b_co}_co(q) ‖ C^{b_time}_time(q))`。
- **超参数**（设计时固定、全程未调）：`k = 14`、`λ = 0.5`、多样性下限 `K = 3`（枚举问题升为 5）、`n_co = 4`、稀有键带 `[2, 10]`、`n_time = 2`、`κ = 18`、`B = 3,072`。因此当门关闭时最后 4 位是 4 个 co-occurrence 轮次，门开启时为 2 个 co-occurrence + 2 个 time 轮次。

### 2.5 答案生成

- 证据包序列化后连同查询交给**唯一一次 reader 调用** `F`（`gpt-4o-mini-2024-07-18`，temperature 0，最多 128 输出 token）。
- 每条证据保留说话人、会话日期与**未改动的源文本**，支持溯源与相对时间解析（相对日期按 `[session_date]` 解析）。
- 若证据不足，reader 返回固定字符串 `Not mentioned in the conversation.`，使弃答行为可被直接度量。

- **Q3 可溯源性与拒答**：由于源轮次逐字保留，任何答案都能回溯到具体轮次与说话人、会话日期；在对抗性问题上 EdgeMem 表现出更强的"证据不足即拒答"能力——匹配指令臂下其精确拒绝率显著高于生成式记忆系统，说明保真存储天然带来更可靠的弃答行为（生成式摘要容易把不存在的细节"编"进记忆，从而诱发幻觉式作答）。
- **Q4 锚点贡献与消融**：Anchor Ladder 显示从 flat BM25 逐级加入 episode、co-occurrence、time 三通道时性能单调提升；其中 **episode 通道是证据核心**（贡献最大），co-occurrence 与 time 提供互补增益。单锚点配置（co-only、time-only）明显弱于组合，验证三类线索的互补性。作者同时坦承 episode 与 co-occurrence 存在重叠（单独 58.18 / 55.39，合并 60.43，低于可加性约 3.4 点），且归因随插入顺序变化，因此对单一模块的"净贡献"应审慎解读。
- **失败案例分析**：审计 27 个复现系统失败后发现，多数错误可追溯到**记忆写入阶段的细节丢失或扭曲**（不可逆），而 EdgeMem 的失败更多来自**检索未命中或 reader 推理失误**——后者至少是"可诊断、可改进"的，而非源头性信息湮灭。

## 7. 方法亮点与贡献

1. **范式层面**：明确提出并验证"保留原始证据 + 结构化组织"可作为生成式记忆管理的**替代范式**，把生成式 LLM 从"记忆全生命周期"收缩到"仅最终答案生成"。
2. **设计不变式**：以 `tok_LLM(Φ) = tok_LLM(Ψ) = 0` 作为硬约束，使成本不随历史规模膨胀，具有清晰的工程与理论意义。
3. **多锚点超图**：用 time / co-occurrence / episode 三类带类型超边统一组织同一份源证据，兼顾"何时发生、讨论什么、属于哪个事件"三条情景记忆检索路径，且构建为追加式、每条轮次只存一份。
4. **确定性、预算感知的检索**：融合三通道并显式分配 token/轮次预算（`κ = 18`、`B = 3,072`），超参数设计时固定、全程未调，降低了过拟合 benchmark 的风险。
5. **可溯源性副产品**：逐字存储与来源标注支持审计与相对时间解析，并使"拒绝回答"成为可直接度量的行为。
6. **评测严谨性**：锁定模型快照实测、逐调用计量、共享答案 prompt 剥离风格、对抗题三口径并预先固定规则、配对 bootstrap 置信区间。

## 8. 局限与批判性评估

- **统计功效有限**：LoCoMo 仅 10 段对话，bootstrap 只有 10 个簇，置信区间较宽，结论的稳健性受样本规模制约。
- **检索层不可直接比较**：LoCoMo 上各系统记忆单元异构（生成笔记、压缩片段、原始轮次），只能端到端比答案质量，无法隔离"检索质量"本身。
- **跨 benchmark 对照不等价**：LongMemEval-S 上生成式构建系统因构建成本随 haystack（约 115k token）放大而**未重跑**，采用转录值（†），与实测条件不完全对等，泛化结论需谨慎。
- **消融归因不唯一**：episode 与 co-occurrence 通道重叠明显，模块净贡献依赖插入顺序，作者亦承认归因存在多解性。
- **超参数固定但来源单一**：所有超参数在 LoCoMo 上一次性设定后固定，虽避免调参，但也未验证在其他数据分布上的普适最优性。
- **本地标注依赖**：锚点质量取决于 spaCy/BM25/dateparser 等本地工具，对非英语、口语化或高度领域化的对话可能退化。
- **评测范围外问题**：真实部署中的同意保留、访问控制与删除策略未纳入评测；论文亦声明未做新数据采集或人类被试研究。

## 9. 启示与展望

- **对记忆系统设计的启示**：不应默认"记忆 = 生成式压缩"。在证据保真与成本敏感的智能体场景中，"原始证据 + 轻量结构"可能是更优的默认起点，生成式组件应作为可选增强而非必需环节。
- **对评测范式的启示**：需要能**隔离记忆质量与答案风格**的评测（如共享 prompt、会话级 Recall/NDCG），以及可度量的拒答/溯源指标，才能公平比较异构记忆系统。
- **可拓展方向**：将多锚点超图扩展到多模态轮次（图像/音频）、增量式与可删除的记忆生命周期管理、以及在更长历史与更大规模对话簇上的统计验证；亦可探索用本地工具与向量混合进一步降低检索未命中率。

## 10. 一句话总结

EdgeMem 用"逐字保留源轮次 + 时间/共现/情节三锚点超图 + 确定性预算感知检索"证明：**不靠生成式记忆管理，也能以极低成本获得不逊甚至更优的智能体长期记忆，并额外收获可溯源性与可靠拒答能力**。
