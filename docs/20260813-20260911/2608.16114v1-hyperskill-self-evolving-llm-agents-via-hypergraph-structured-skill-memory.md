## 摘要
随着智能体任务日益复杂，LLM 智能体愈发依赖经验记忆来跨任务复用程序性知识。有效的记忆设计必须同时解决存储什么、记忆如何组织与检索，以及记忆如何演化这三个问题。现有系统仅部分地解决上述问题：它们将轨迹、洞见或工作流存储为孤立条目，丢弃了子任务与可复用技能之间的组合关系；通过扁平化的嵌入相似度进行检索，忽略了关系信号；并且在维护记忆时未能利用其关系结构。我们提出 HyperSkill，一个基于超图的记忆框架，可同时改进上述三方面。HyperSkill 将记忆表示为包含两类节点的超图——子任务步骤与可复用技能，其中每条超边连接来自单条轨迹的子任务与技能。双路径检索同时在子任务层与轨迹层进行查询，并根据技能在检索到的轨迹中的共现情况对技能进行排序。周期性的结构感知维护通过质量加权传播剪除低效用节点并合并冗余技能。在 xBench、GAIA 和 WebWalkerQA 上，使用 GPT-4o 与 Qwen3-30B-A3B，HyperSkill 优于十个记忆基线，在 GAIA 上最高提升 +11.51，在 WebWalkerQA 上最高提升 +11.18。

## Abstract
As agentic tasks grow in complexity, LLM agents increasingly rely on experiential memory to reuse procedural knowledge across tasks. Effective memory design must jointly address what to store, how memory is structured and retrieved, and how memory evolves. Existing systems tackle each only partially: they store trajectories, insights, or workflows as isolated entries, discarding compositional relationships among subtasks and reusable skills; retrieve by flat embedding similarity that ignores relational signals; and maintain memory without leveraging its relational structure. We propose HyperSkill, a hypergraph-based memory framework that jointly improves all three. HyperSkill represents memory as a hypergraph with two node types, subtask steps and reusable skills, where each hyperedge links the subtasks and skills from a single trajectory. Dual-path retrieval queries both subtask and trajectory levels, ranking skills by co-occurrence across retrieved trajectories. Periodic structure-informed maintenance prunes low-utility nodes and merges redundant skills via quality-weighted propagation. Across xBench, GAIA, and WebWalkerQA with GPT-4o and Qwen3-30B-A3B, HyperSkill outperforms ten memory baselines, yielding gains of up to +11.51 on GAIA and +11.18 on WebWalkerQA.

## 一、核心问题与研究动机

- **背景**：随着智能体任务复杂度上升，LLM 智能体越来越依赖**经验记忆（experiential memory）**——不是存储外部事实，而是把自身历史轨迹蒸馏为可复用知识，从而实现"自进化"（每经历一条轨迹就变强，而非每次从零开始）。
- **问题拆解**：论文把经验记忆设计归结为三个基本问题：
  1. **存什么（what to store）**；
  2. **如何组织与检索（how structured & retrieved）**；
  3. **如何演化（how memory evolves）**。
- **现有系统的三重缺陷**：
  - *存什么*：早期存原始轨迹，后续抽象为洞见 / 工作流 / 技能，但**均以孤立条目存储**，丢弃了子任务分解与可复用技能之间的组合关系，导致跨任务的组合式规划知识无法迁移。
  - *如何检索*：主流是扁平向量库 / JSON 存储 + 嵌入相似度检索，少数用图结构，但**成对（pairwise）边会把 n 元共现关系拆散成互不相连的二元链接**，丢失一条轨迹的联合上下文。
  - *如何演化*：多数系统**无条件累积**，少数只做轻量剪枝 / 去重 / 合并，且**逐节点独立操作，不利用图拓扑**，也未联合考虑质量信号与结构信号。
- **结构性根因**：一条轨迹本质上是"子任务 × 技能 × 结果"的 **n 元关联**，而非单一知识单元；扁平列表与成对边只能有损表示。
- **整体含义**：论文主张用**超图（hypergraph）**原生表示这种 n 元关联——一条超边可同时连接任意多个节点，从而用一个统一结构同时回应上述三个问题。

## 二、方法论：HyperSkill

### 2.1 核心思想
将经验记忆建模为超图 \(G=(V,E)\)，节点分两类（子任务步骤、可复用技能），**每条超边对应一条完整轨迹**，把该轨迹的子任务、技能、任务描述、蒸馏教训与效用分数绑定在一起；检索用双路径，维护用质量加权的结构传播。

### 2.2 记忆结构
- **节点** \(v_i \triangleq (c_i, \ell_i, \gamma_i)\)：\(c_i\) 为自然语言内容，\(\ell_i \in \{u, s\}\) 为类型标签，\(\gamma_i \in [0,1]\) 为**效用分**。
  - **子任务节点 \(V^u\)**：编码任务分解中的一步（步骤描述 + 前置条件），承载组合式工作流结构。
  - **技能节点 \(V^s\)**：由**结果条件化提示**抽取，含策略标签 + "做什么 / 何时用 / 为何有效（或失败）"的描述；成功轨迹产出正向策略，失败轨迹产出错误模式（error pattern）。
- **效用分更新**（对每次参与检索的节点 / 超边）：成功则 \(\sigma(\cdot)+1\)，并用步数 \(T_i\) 更新平均步数 \(\bar T(\cdot)\)，再计算
  \[
  \gamma(\cdot)=\beta\cdot\frac{\sigma(\cdot)}{\nu(\cdot)}+(1-\beta)\cdot\Bigl(1-\frac{\bar T(\cdot)-T_{\min}}{T_{\max}-T_{\min}}\Bigr)
  \]
  其中 \(\nu\) 为被检索次数，\(\sigma\) 为成功次数，\(\beta\) 平衡"成功率"与"步数效率"。
- **超边** \(e_j \triangleq (V_j, d_j, \ell_j, \gamma_j)\)：\(V_j = V^u_j \cup V^s_j\) 为该轨迹的子任务与技能节点，\(d_j\) 为原任务描述，\(\ell_j\) 为蒸馏教训；检索表示 \(h_e=\phi(d_j \parallel \ell_j)\)（拼接任务描述与教训，兼顾表面措辞与可迁移模式）。

### 2.3 双路径检索与技能排序
- **子任务路径（subtask path）**：先用 LLM 把新任务 \(d_q\) 分解为细粒度计划 \(P_0=\{d_1,\dots,d_m\}\)，整体编码 \(h_{P_0}=\phi(P_0)\)，检索最相似的 top-\(k_u\) 个子任务节点 \(R_u\)；由节点—超边关联扩展出候选轨迹集 \(E_{\text{sub}}=\{e\mid V_e\cap R_u\neq\varnothing\}\)。该路径能召回"任务表述差异大但程序性子结构相同"的轨迹。
- **轨迹路径（trajectory path）**：用 \(h_{d_q}=\phi(d_q)\) 直接与超边表示 \(h_e\) 匹配，取 top-\(k_e\) 得 \(E_{\text{traj}}\)。
- **融合**：\(E^* = E_{\text{sub}} \cup E_{\text{traj}}\)，其教训集合 \(L_q=\{\ell_e \mid e\in E^*\}\) 作为轨迹级上下文。
- **技能共现排序**（关键创新）：候选技能池为 \(R_s=\bigcup_{e\in E^*} V^s_e\)；对每个候选统计共现次数
  \[
  \kappa(v)=\bigl|\{e\in E^* \mid v\in V_e\}\bigr|
  \]
  取 top-\(k_s\) 作为执行指导，同分时用与 \(d_q\) 的嵌入相似度打破平局。理由：技能节点是**跨轨迹去重复用**的，在某技能于多条被检索到的相关轨迹中反复出现，说明它确实在相关情境中被用过——这是纯语义相似度无法提供的结构信号。

### 2.4 执行与记忆更新
- 检索上下文 \((S_q, L_q)\) **每任务只组装一次并全程固定**；每步动作 \(a_t \sim \pi_\theta(\cdot \mid o_t, S_q, L_q, \text{hist}_{t-w:t-1})\)。
- 任务结束后，用结果条件化 LLM 调用从完整轨迹抽取新技能 \(S^{\text{new}}_i\) 与教训 \(\ell_{e_i}\)；子任务节点 \(U^{\text{new}}_i\) 直接来自 \(P_0\)。
- **插入前去重**：新技能与既有技能节点嵌入相似度超过 \(\delta_{\text{dedup}}\) 则合并到最近邻，而非新增重复节点。
- 新增一条超边 \(e_{\text{new}}=(U^{\text{new}}_i\cup S^{\text{new}}_i,\ d_q,\ \ell_{e_i})\)，并重算所有参与检索元素的 \(\gamma\)。

### 2.5 结构感知的记忆演化（每 \(\lceil 0.1\times N\rceil\) 个任务触发一次）
- **质量驱动剪枝**：删除满足 \(\nu(v)\ge N_{\min}\) 且 \(\gamma(v)<\tau_{\text{prune}}\) 的节点（被反复检索却持续拖累表现），并从所有超边成员关系中移除。
- **结构感知合并**（仅对技能节点 \(V^s\)；子任务节点被明确排除，因为合并规划步骤会破坏任务分解的组合结构）：
  1. 构造**质量加权共现矩阵** \(W_{ij}=\min(\gamma(v_i),\gamma(v_j))\cdot\sum_{e:\,v_i,v_j\in V_e}\frac{1}{|V_e|}\)；其中 \(1/|V_e|\) 按同质性假设归一化（共享小超边的节点更可能相似），\(\min(\gamma)\) 保证只有双方都有用时才产生高权重。
  2. 用 \(L\) 步对称传播得到**结构嵌入** \(\tilde Z = SZ\)，其中 \(S=(1-\alpha)^L\hat W^L+\alpha\sum_{l=0}^{L-1}(1-\alpha)^l\hat W^l\)，\(\hat W=\hat D^{-1/2}(W+I)\hat D^{-1/2}\)；由于效用已编码进 \(W\)，\(\tilde Z\) 同时反映结构共现与技能质量。
  3. 相似度 \(\text{sim}(\tilde z_a,\tilde z_b)\ge\delta_{\text{merge}}\) 的技能对交给 LLM 基于两者内容与共享轨迹片段**合成一个更高阶技能**，并重分配所有超边成员关系。

### 2.6 整体算法流程（文字版）
任务到达 → LLM 分解为子任务计划 → 子任务路径检索 + 轨迹路径检索 → 融合为 \(E^*\) → 在 \(E^*\) 的技能并集上按共现次数排序取 top-\(k_s\) → 以 \((S_q, L_q)\) 固定上下文执行任务 → 结束后抽取新技能与教训、去重、插入新超边、更新效用分 → 每约 10% 任务量触发一次剪枝与合并。
