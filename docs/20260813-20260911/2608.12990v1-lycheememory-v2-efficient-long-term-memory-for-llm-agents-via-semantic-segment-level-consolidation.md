## 摘要
长时程LLM智能体必须保留过往交互中的信息，以支撑未来任务。现有记忆系统通常依赖即时整合，即在每次交互后调用LLM来提取、总结或更新记忆。这种设计使得随着对话增长，记忆构建成本不断攀升。粗粒度摘要虽可降低构建成本，却可能丢弃细粒度的上下文证据；而更大的检索上下文或多跳LLM推理则会把开销转移到查询阶段。我们提出LycheeMemory V2，一个高效长期记忆框架，以语义片段级整合替代轮次级整合。LycheeMemory并非对每次交互都进行整合，而是将多轮交流批量归并为片段，并将每个最终确定的片段编码为与上下文无关的类型化记忆记录。片段级批处理降低了LLM编码频率，而语义边界检测相比固定窗口批处理有助于保留连贯的事件级与时序证据。所得记录通过轻量级结构化索引进行组织，以支持查询规划式的证据检索。使用GPT-4.1-Mini的实验表明，LycheeMemory取得了当前最优性能，在LoCoMo上达到89.22%，在LongMemEval-S上达到92.20%。与A-Mem相比，它在不增加查询阶段token用量的情况下，将LoCoMo上的构建token减少了86.0%，将LongMemEval-S上的构建token减少了75.9%。更广泛地说，我们的结果表明，长期智能体记忆的准确率—成本权衡不仅取决于保留了什么信息，还取决于以何种粒度对其进行整合。

## Abstract
Long-horizon LLM agents must preserve information from past interactions to support future tasks. Existing memory systems typically rely on eager consolidation, invoking LLMs after each interaction to extract, summarize, or update memories. This design makes memory construction increasingly costly as conversations grow. Coarse summarization can reduce construction cost but risks discarding fine-grained contextual evidence, whereas larger retrieval contexts or multi-hop LLM reasoning shift the overhead to query time. We present LycheeMemory V2, an efficient long-term memory framework that replaces turn-level consolidation with semantic segment-level consolidation. Instead of consolidating every interaction, LycheeMemory batches multiple exchanges into segments and encodes each finalized segment into context-independent typed memory records. Segment-level batching lowers LLM encoding frequency, while semantic boundary detection helps preserve coherent event-level and temporal evidence compared with fixed-window batching. The resulting records are organized with lightweight structured indexes for query-planned evidence retrieval. Experiments using GPT-4.1-Mini show that LycheeMemory achieves state-of-the-art performance, reaching 89.22% on LoCoMo and 92.20% on LongMemEval-S. Compared with A-Mem, it reduces construction tokens by 86.0% on LoCoMo and 75.9% on LongMemEval-S without increasing query-time token usage. More broadly, our results suggest that the accuracy--cost trade-off of long-term agent memory depends not only on what information is retained, but also on the granularity at which it is consolidated.

## 1. 核心问题与整体含义

**研究背景**
- LLM 智能体正从单轮应答者转向持久化助手，需在长时程场景（个人助理、客服、辅导、任务型对话）中跨多次交互记住用户偏好、历史事件、演化事实、约束与失败经验。
- 由于上下文窗口无法可靠容纳无限历史，主流做法是引入外部记忆模块，对过往对话进行提取、更新、组织与检索。

**核心痛点（论文归纳的三种现有范式）**
- **即时整合（eager consolidation）**：每轮/每次短交互后即调用 LLM 做摘要、抽取事实、更新记忆。效果好，但把记忆构建变成高频 LLM 操作，token 成本随对话增长迅速累积。
- **粗粒度摘要**：降低构建成本，但会丢弃实体、时间表达、指代关系等细粒度证据，而长期记忆问答恰恰依赖这些细节。
- **查询时补偿**：扩大 top-k 检索或采用 LLM 多跳检索可提升召回，但把开销转移到查询阶段。

**核心命题**
- 关键挑战不是"存更多历史"，而是**在恰当的粒度上保留足够证据，同时控制构建与检索两侧成本**。
- 论文主张：长期记忆的精度—成本权衡不仅取决于*保留了什么*，还取决于*以何种粒度整合*。记忆构建粒度本身就是一个重要的效率杠杆。

## 2. 方法论

### 2.1 核心思想
以**语义片段级整合**替代**轮次级整合**：不再对每次交互调用 LLM，而是把多轮交流缓冲归并为语义连贯的片段，片段最终确定时才触发一次 LLM 编码，产出与上下文无关的类型化记忆记录。

### 2.2 在线语义分割（决定何时整合）
- 对每个 exchange 用 `text-embedding-3-small` 编码，维护当前片段质心 c_k 与最近一次 exchange 嵌入 h_k。
- **语义惊奇**：`s_t = 1 - max(sim(e_t, c_k), sim(e_t, h_k))`，衡量新交互是否偏离片段全局主题与局部对话轨迹。
- **连贯性下降**：以 `Coh(V) = (1/|V|) Σ sim(v, c_V)` 度量片段内聚度，`d_t = max(0, Coh(S_k) - Coh(S_k ∪ {x_t}))`，表示加入该交互后片段主题一致性的损失。
- **边界概率**：`p_t = σ(b + w_s·φ(s_t) + w_c·d_t + w_l·L_t + w_n·N_t)`，融合语义惊奇（局部归一化）、连贯性下降、token 长度压力与轮次压力。
- 当 `p_t` 超过阈值 δ（默认 0.50）或触及硬 token 上限时片段定稿；否则追加进当前片段。
- 该过程**完全基于 embedding 与确定性打分，不产生 LLM 推理**，中途 exchange 只做缓冲。
- 编码调用次数从 T（每轮一次）降为 |S|（每片段一次，LoCoMo 上平均 5.8 轮/片段）。

### 2.3 片段级记忆编码（写入什么）
- 对定稿片段 S_k，编码器接收片段文本 + 来自近期片段的紧凑参考上下文 ρ_k，输出 `(R_k, d_k) = Encode(S_k, ρ_k)`。
- **一次 LLM 调用完成三件事**：抽取原子信息单元、消解共指与省略、基于会话时间戳归一化相对时间表达。
- 每条记录：`r_i = (id_i, τ_i, text_i, E_i, K_i, T_i, src_i)`，即标识、记忆类型、自包含自然语言陈述、实体集、主题标签、归一化时间、来源轮次溯源。
- 记忆类型为有限 schema：fact、preference、event、constraint、procedure、failure_pattern、tool_affordance。
- **跨片段连续性**：编码器同时返回消歧状态 d_k（已解析别名、规范实体名、指代关系），下一片段的参考上下文 `ρ_{k+1} = [d_k; Recent(R_{k-m:k})]`，并截断到固定预算（消歧上下文 1200 字符、同会话参考上下文 2400 字符、保留 12 条近期记录），防止 prompt 随历史无限增长。

### 2.4 结构化证据组织
- 从编码器已产出的元数据直接构建索引，**不额外调用 LLM**，仅做 embedding 与记账。
- 向量库（LanceDB）存记录嵌入用于直接语义检索；结构化库（SQLite + FTS5）维护五类证据节点：
  - entity 节点、topic 节点、entity-topic 共现节点、temporal 节点（日级/月级）、event-frame 节点（同一片段产出的记录分组，保留来源会话与轮次范围）。
- 每个节点存可搜索文本、可选嵌入、指向记录指针；保留文本上不同的陈述为独立记录，**不做近似语义合并、不推断覆盖关系、不关闭旧记录有效期**，把冲突消解留给检索与答案生成。

### 2.5 计划引导的多路由检索
- **一次 LLM 规划调用**：`Π(q, H_q) = (y, {R_1, ..., R_m})`，y 为问题类型（single / aggregate / temporal / comparison / personalized_advice / prior_assistant_response / other），每条路由 `R_j = (g_j, Q_j, C_j, T_j)` 含目标、查询、结构化约束与可选时间约束。
- 问题类型决定通道权重、各通道候选上限与扩展深度。
- **四路并行召回**：直接记录向量召回、证据节点召回（实体/主题/实体-主题/事件框架，命中后展开到关联记录）、时间召回（精确日期或区间过滤）、原始轮次召回（找回未被整合为类型化记录的逐字证据）。
- **融合与选择**：路由内可选 cross-encoder（bge-reranker-v2-m3）重排；路由间用 RRF 融合 `RRF(d) = Σ_j 1/(κ + rank_j(d))`，κ=60.0；再做多样性感知选择（MMR 风格，`s_select = 0.75 s_rel - 0.25 s_sig`，最终分 `s_final = 0.82 s_best + 0.18 s_route`）。
- 检索后仅规划一步为生成式操作，其余召回、扩展、重排、融合、选择均为 embedding 查询、结构化过滤或算术打分，**不消耗生成式 token**。
- 证据冲突时，答案模型被指示优先采用最新且有支撑的信息。

- **两侧成本曲线更优**：在精度—成本散点图上，LycheeMemory V2 位于帕累托前沿左上方，即在同等构建/查询 token 预算下取得更高精度，或在同等精度下消耗更少 token。
- **消融揭示关键归因**（LoCoMo + GPT-4.1-Mini）：
  - 构建侧：eager construction（每轮触发）精度与本文相当但构建 token 激增，说明**收益主要来自语义边界而非批处理本身**；fixed-window consolidation（固定窗口）token 同样低但精度明显下降，说明**低成本的来源不能以牺牲语义完整性为代价**。
  - 表示侧：summary-level records 精度下降，验证细粒度类型化记录优于粗摘要；w/o cross-segment context 在多跳、时序与知识更新类问题上退化，印证跨片段消歧上下文对长期一致性的作用。
  - 检索侧：record-vector only 与 w/o query planner 降幅最大，w/o fusion/rerank/div 次之，说明**多路由召回 + 问题类型规划**是精度提升的主要来源，融合与重排提供稳定增益但非决定性。
- **边界阈值不敏感**：δ 在 0.40–0.60 区间内精度变化平缓，δ=0.50 为较优折中；δ 过小导致片段过碎、编码调用增多，δ 过大导致片段过长、细节被稀释，呈现典型"粒度—成本"权衡曲线。

## 7. 讨论、局限与启示

**论文自述的局限**
- 部署维度未覆盖：数据库访问延迟、嵌入索引的存储与更新成本、生产环境的监控与回滚机制均未评估，token 并非唯一成本。
- 分割器依赖嵌入质量与超参数（阈值 δ、硬 token 上限、长度/轮次压力权重），跨语言、跨领域（如代码、结构化日志）的迁移性未验证。
- 编码 schema 为有限固定类型集，面对新领域可能需要扩展；不做冲突消解、不关闭旧记录有效期，把负担推给答案模型，在高度矛盾或需要强一致性的场景下可能产生歧义。

**客观评述**
- 贡献在于**把"整合粒度"显式提升为一等设计变量**：此前工作多在"何时整合"（eager vs. 批处理）上做文章，本文进一步论证"以什么单元整合"（片段 vs. 轮次）才是更有效的效率杠杆，且给出了无需 LLM 参与的在线分割实现，工程可落地性强。
- 方法组合的每一环都尽量避开生成式调用（分割、索引、召回、融合、选择均为 embedding/规则/算术），使成本模型清晰可预测，这一点比单纯的精度数字更具方法论价值。
- 公平性上，与 baseline 共享骨干、数据划分与裁判，横向对比可信度较高；但**单次运行、无方差报告、消融仅限单一基准与单一骨干**是主要短板，若关键结论（如 +27pp 多跳）能在多骨干、多基准上复现，说服力会显著增强。
- Full Context 在长上下文上的衰减、以及各类记忆系统在 LongMemEval-S 上的普遍低分，提示当前 benchmark 对骨干长上下文能力的敏感度较高，结论的"模型无关性"仍需更多证据。

**对后续研究的启示**
- 粒度自适应的记忆构建（按对话主题漂移速度动态调整片段长度）可能进一步优化成本曲线。
- 将冲突消解、时效性管理从"检索后指示模型"前移到"编码时轻量标注"，或能兼顾低成本与一致性。
- 需要更细粒度的成本核算协议（含嵌入、存储、检索延迟）与多轮运行统计，才能支撑长期记忆系统的可复现比较。

## 8. 一句话总结

LycheeMemory V2 通过在**语义片段粒度**上做一次性 LLM 整合（在线无 LLM 分割 + 片段级类型化编码 + 元数据驱动的结构化索引 + 计划引导的多路由检索），在 LoCoMo 与 LongMemEval-S 上同时实现了**精度领先**与**构建/查询 token 双侧大幅下降**，其核心洞见是：长期记忆的效率杠杆不在"存多少"，而在"以何种粒度整合"。
