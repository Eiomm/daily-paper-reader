## 摘要
从过去的成功中提取技能对于大型语言模型（LLM）智能体的高效演化至关重要。主流的智能体自演化范式通常依赖于一个核心假设：为 LLM 配备从成功轨迹中提取的技能记忆，会单调提升其问题求解能力。然而，探针分析表明，仅从成功轨迹中提取技能会使模型陷入技能模仿陷阱。对于与过去成功案例相似但需要不同工具的任务，检索更多技能反而会增加模型对错误工具调用的信心——过程性技能相比无记忆基线将错误工具边际提高了 47%。为克服这一局限，我们提出边界感知技能记忆（BASM），它为每个技能增加了显式的边界字段——适用条件、风险线索、规避规则和恢复说明。这些字段将每个检索到的技能从无条件的动作模板转变为状态条件化的指导：当技能条件成立时，智能体应用该技能；当条件不成立时，抑制不适用的工具调用；当执行失败时，进行有针对性的修复。在三个智能体基准和四个模型规模上，BASM 始终优于成功蒸馏的技能记忆基线：在 AppWorld 上任务成功率最高提升 23.8%，在 BFCL 上准确率最高提升 5.0%，在 AgentDojo 上将攻击成功率降低 4.6%，同时相较于无记忆基线，将 AppWorld 平均步数最多减少 6.6%。

## Abstract
Extracting skills from past successes is critical for the efficient evolution of Large Language Model (LLM) agents. Prevailing agent self-evolution paradigms typically rely on a core assumption: equipping LLMs with skill memories derived from successful trajectories will monotonically improve their problem-solving capabilities. However, probe analyses reveal that extracting skills solely from successful trajectories traps the model in a \textbf{Skill Imitation Trap}. For tasks that resemble past successes but require different tools, retrieving more skills paradoxically increases the model's confidence in wrong tool calls---procedure skills raise the wrong-tool margin by $47\%$ over a memory-free baseline. To overcome this limitation, we propose \textbf{Boundary-Aware Skill Memory} (BASM), which augments each skill with explicit boundary fields---applicability conditions, risk cues, avoidance rules, and recovery notes. These fields transform each retrieved skill from an unconditional action template into state-conditioned guidance: the agent applies the skill when its conditions hold, suppresses inapplicable tool calls when they do not, and issues targeted repairs when execution fails. Across three agent benchmarks and four model scales, BASM consistently outperforms success-distilled skill-memory baselines: it improves task success rate by up to $23.8\%$ on AppWorld, accuracy by up to $5.0\%$ on BFCL, and reduces attack success rate by $4.6\%$ on AgentDojo, while simultaneously reducing average AppWorld steps by up to $6.6\%$ relative to the memory-free baseline.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体在复杂交互环境中需要多步工具调用、API 编排与长程规划，技能获取（从历史轨迹中提取、存储、复用过程性知识）已成为智能体自演化的关键机制。
- **核心假设的隐患**：现有范式（Voyager、ExpeL、SkillX、Skill0 等）普遍假定“从成功轨迹蒸馏的技能，一旦被检索为相关，就应带来正向迁移”，即技能记忆会**单调提升**问题求解能力。
- **发现的问题——技能模仿陷阱（Skill Imitation Trap）**：
  - 对于与过去成功案例语义相似但实际需要不同工具的任务，检索更多技能反而**放大**模型对错误工具的偏好。
  - 探针测量显示：过程性技能（Proc. Skill）相比无记忆基线，将错误工具边际（wrong-tool margin）提高 **47%**（k=0 时 7.31 → k=2 时 10.71）。
  - 机制上：成功蒸馏记忆使决策 token 的注意力偏向过程性内容而非边界线索，把检索到的技能当作**无条件动作模板**。
- **整体含义**：技能记忆的可靠性瓶颈不在于“程序知识不足”，而在于**缺乏显式的有效性边界**；论文主张技能应编码“何时不应模仿”，实现从盲目模仿到**有效性限定的迁移（validity-scoped transfer）**。

## 2. 方法论：边界感知技能记忆（BASM）

### 2.1 核心思想
- 将每个检索到的技能从**无条件动作模板**转变为**状态条件化证据**：条件成立时应用、不成立时抑制、执行失败时局部修复。
- 通过离线提取把边界证据从轨迹中“搬运”到在线检索、提示格式化与决策时检查三个阶段。

### 2.2 七槽技能 Schema
技能表示为七元组：
- **过程性核心（Procedural）**：目标 g、过程 π、工具集 T
- **边界组件（Boundary）B(s) = A ⊕ R ⊕ N ⊕ F**：
  - **适用条件 A**：何时可安全调用
  - **风险线索 R**：使相似技能不安全的观测
  - **规避规则 N**：特定状态下应抑制的动作/参数
  - **恢复说明 F**：局部失败后的一步修正建议

### 2.3 关键技术细节与流程

- **离线技能库构建**：
  - 从成功轨迹 K⁺ 与失败/部分失败轨迹 K⁻ 中提取锚点，分**步骤级**（功能技能）与**工具级**（原子技能）两种粒度。
  - 提取器输入成功上下文 τ⁺（提供 g, π, T）与邻近失败上下文 τ⁻（仅用于生成 R, N, F）。
  - 经确定性验证算子 ψ（严格 JSON 解析、必填字段、列表型边界槽、非空风险/规避、工具 schema 校验），失败重试后仍不合格则丢弃，形成 **precision-first** 技能库。

- **检索与提示格式化**：
  - 多视图检索分数：`score = λ_sem·cos(e(xt), e(vs)) + λ_tool·J(Txt, Ts) + λ_step·overlap(xt, gs, πs)`，取 Top-K。
  - **固定 token 预算**：过程性内容始终暴露；边界字段仅在边界相关性 r_B(xt, s) 超过阈值 γ 时才纳入，且受边界 token 预算 β 限制（动机来自“无差别检索会放大错误工具偏好”的探针发现）。

- **边界条件化执行**：
  - 边界检查器比较提议的工具调用 a_t 与检索到的边界字段，对违反适用条件、命中规避规则或重复已知失败模式的调用进行**阻断或修正**。
  - 判定函数 `G = ∏ I[a_t ⊭ N(s) ∧ xt ⊨ A(s)]`，先做确定性字符串/schema 检查，歧义的自然语言条件再用 LLM 辅助判断。

- **运行时局部修复**：
  - 在状态化多轮环境中，当观测 o_{t+1} 指示局部失败时，修复模块检索针对性提示 `h_t = Repair(xt, a_t, o_{t+1}, Sk)`，注入下一步决策，替代完整技能重检索。
  - 单轮设置中 F 仅影响推理时的工具选择。

## 6. 主要结论与发现

- **技能模仿陷阱在基准规模上真实存在**：Proc. Skill 在 Qwen3-8B 与 14B 的 BFCL 上均低于 Base，证明纯过程性记忆会在不可用状态下放大错误工具偏好。
- **BASM 持续优于成功蒸馏基线**：
  - AppWorld 成功率最高提升 **23.8%**；BFCL 准确率最高提升 **5.0%**。
  - AgentDojo 攻击成功率降低 **4.6%**；AppWorld 平均步数相对无记忆基线最多减少 **6.6%**（效率不因记忆而下降）。
  - Qwen3-14B 上实现**效用与安全的 Pareto 改进**（最高 Utility + 最低 ASR）。
- **机制归因**：
  - 边界字段充当**状态条件化注意力调制器**：Tok 状态下边界/过程注意力比低（0.15），Twrong 上升（1.23），Trepair 最高（1.81）。
  - 同提示 knockout 边界注意力后，错误工具偏好回升 +3.45 logits，**恢复 69.4% 的模仿陷阱效应**；随机同长度与过程 span knockout 不产生同样效果。
  - 边界 knockout 选择性提高 Twrong–wrong（+0.27），几乎不影响 Twrong–correct（+0.04），说明不是对工具使用的普遍惩罚。
  - 线性探针未发现稳定的适用性特征，说明 BASM 作用于**决策时刻的动态注意力**，而非注入静态隐藏状态标签。
- **组件互补性**：边界条件化提示主要提升函数选择精度（BFCL），运行时修复在状态化多步环境（AppWorld）中带来收益；二者缺一不可——Repair-Only 在 BFCL 无增益且 AppWorld 低于 Base，Prompt-BASM 在 AppWorld 也低于 Base。
- **部分边界反而有害**：仅增加适用条件（App. Skill）虽提升 BFCL 1.37 点，但 ASR 上升 0.53 点，说明不完整的边界规范可能增加对表面满足条件的注入指令的敏感性。

## 7. 优点

- **问题识别具有反直觉性与机制深度**：揭示“更多技能记忆反而更差”的技能模仿陷阱，并用注意力归因、logit 边际、同提示 knockout 构建了较完整的因果证据链。
- **方法设计简洁且可解释**：七槽 schema 以自然语言字段显式表达边界，便于人工检查与调试；检索、格式化、执行三阶段均有明确控制点。
- **控制变量严谨**：等长度 padding 控制、等 token 配对、随机 span knockout、过程 span knockout 等多重对照，有效排除 prompt 长度与格式化的替代解释。
- **跨规模、跨任务一致性**：从 8B 到 397B、从单轮函数调用到状态化多步任务再到对抗安全，结论保持稳健。
- **同时改善效用、安全与效率**：在 AppWorld 上提升成功率的同时减少平均步数，并在 14B 上实现效用–安全 Pareto 改进。
- **消融设计有信息量**：清晰区分“提示侧边界条件化”与“运行时修复”的互补作用，并揭示不完整边界（仅适用条件）可能带来的安全副作用。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量、训练/推理时长，难以评估方法的资源开销与可复现成本。
