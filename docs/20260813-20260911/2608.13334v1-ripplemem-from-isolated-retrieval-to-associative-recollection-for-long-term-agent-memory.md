## 摘要
基于LLM的智能体越来越依赖外部记忆来支持长时程推理与交互。然而，主要瓶颈并非简单地存储过往经验，而是在相关信息分散于大量交互中时，恢复出正确的证据集合。现有方法难以解决这一访问问题。全上下文方法需要进行有噪声的长上下文搜索，扁平检索往往返回孤立且不完整的记录，而基于图的记忆系统构建成本高昂，同时会压缩丰富的事件上下文。我们提出RippleMem，一种长期记忆系统，它用自适应联想回忆取代一次性检索。受线索依赖的情景提取和联想补全启发，RippleMem将交互历史存储为线索丰富的情景记忆单元，并将其组织在以事件为中心的记忆图中。给定查询，它首先通过混合线索回忆相关记忆锚点，然后沿语义和结构关联从这些锚点扩展，以恢复缺失的支持证据。这样，最初回忆起的记忆不仅作为答案上下文，还作为补全回答问题所需证据的线索。在LoCoMo和LongMemEval-S上的实验表明，RippleMem在所评估的设置中取得了最佳总体性能，在LoCoMo上将LLM-as-a-Judge准确率提升3.95%，在LongMemEval-S上最高提升11.87%，同时将图构建成本降低约30倍。

## Abstract
LLM-based agents increasingly rely on external memory to support long-horizon reasoning and interaction. However, the main bottleneck is not simply storing past experience, but recovering the right set of evidence when relevant information is distributed across many interactions. Existing approaches struggle with this access problem. Full-context methods require noisy long-context search, flat retrieval often returns isolated and incomplete records, and graph-based memory systems can be expensive to construct while compressing rich event context. We introduce RippleMem, a long-term memory system that replaces one-shot retrieval with adaptive associative recollection. Inspired by cue-dependent episodic retrieval and associative completion, RippleMem stores interaction history as cue-rich episodic memory units and organizes them in an event-centric memory graph. Given a query, it first recalls relevant memory anchors through hybrid cues, then expands from these anchors along semantic and structural associations to recover missing supporting evidence. In this way, initially recalled memories serve not only as answer context, but also as cues for completing the evidence needed to answer. Experiments on LoCoMo and LongMemEval-S show that RippleMem achieves the best overall performance across evaluated settings, improving LLM-as-a-Judge accuracy by 3.95% on LoCoMo and up to 11.87% on LongMemEval-S, while reducing graph construction cost by about 30x.

## 1. 核心问题与整体含义

- **研究背景**：基于 LLM 的智能体需要在长时程推理与交互中保持记忆能力，记忆已从"辅助组件"变成核心能力——需要保存过去的交互信息，并在后续查询依赖早期事件、偏好或决策时将其作为证据取回。
- **真正的瓶颈不在"存"而在"取"**：长时程交互中，回答一个查询所需的信息往往不包含在单条语句或单条记忆记录里，而是**分散在时间上相隔很远的多个会话中**，混杂在大量日常对话里，只有多个片段被**共同恢复**时才可用。
- **现有方案的三种失败模式**（论文 Figure 1 给出示例）：
  - **全上下文（Full-Context）**：需要在含噪长上下文中搜索，且存在 lost-in-the-middle / 证据退化问题；
  - **扁平检索**：只返回最直接匹配的记录，常常是孤立且不完整的片段；
  - **图记忆系统**：构建代价高，同时在压缩时丢失丰富的事件上下文；无导向的图扩展可能走到"相关但不支持"的记忆上。
- **论文提出的核心问题**：*当最初检索到的记忆相关但不完整时，记忆访问应如何继续，以补全回答所需的缺失支持证据？*
- **核心主张**：长期记忆访问应当是**证据条件化（evidence-conditioned）**的——被回忆起的记忆不只是检索的终点（答案上下文），更应成为**寻找缺失证据的线索**。
- **总体含义**：把记忆访问从"一次性查询匹配 + 无导向图遍历"转变为"受控的证据补全"，并用"涟漪（ripple）"作比喻：从初始接触点出发，沿相连的情节记忆局部扩散。

## 2. 方法论

### 2.1 整体框架：Write–Read 双阶段

- **Write 阶段**：把交互历史转成**线索丰富的情节记忆单元**，并用**以事件为中心的记忆图**把它们连接起来，形成可寻址的事件记忆空间。
- **Read 阶段**：**自适应联想回忆**先召回候选证据，必要时从显著锚点沿关联扩展补全缺失支持；**证据组装**将最终证据整合为紧凑上下文供生成使用。
- 认知依据（作者声明是**设计直觉而非机制主张**）：事件分割（Zacks et al., 2007; Baldassano et al., 2017）、编码特异性（Tulving & Thomson, 1973）、海马索引与模式补全（Norman & O'Reilly, 2003）。

### 2.2 线索丰富的情节记忆构建

- 将对话轨迹切分为**带局部重叠的连续轮次窗口** `{W_t}`（LoCoMo 40 轮 / 重叠 2 轮；LongMemEval-S 10 轮 / 无重叠），以保留跨窗口连续性。
- 每个窗口交给**模式引导的 LLM 抽取器**，输出 JSON 记忆单元列表；若窗口内没有值得保存的持久事件/偏好/承诺/观察/计划，可返回空列表；输出需通过模式校验后才写入记忆库。
- **记忆单元模式**：`m_i = (r_i, v_i, P_i, L_i, T_i)`
  - `r_i`：规范化的**事件重述**，可脱离原对话窗口独立理解；
  - `v_i`：`r_i` 的稠密向量表示（支持语义访问）；
  - `P_i, L_i, T_i`：落地的人物、地点、时间线索（支持结构化/跨线索关联）。
- **抽取约束**：把依赖说话人的指代解析为显式人名；仅在对话时间戳支持时把相对时间锚定为绝对区间；多事件窗口拆分为可独立检索的单元；**无法落地的字段留空而不做推断**。
- 关键点：写入阶段不只是"压缩成摘要"，而是构建**可按线索寻址的事件记忆**。

### 2.3 事件中心记忆图

- 记忆库组织为**稀疏加权图** `G = (M, E)`，`E = E_sem ∪ E_str`，每个保留的边携带关联分数作为权重，作为潜在回忆路径。
- **语义关联**：`s_sem(i,j) = cos(v_i, v_j)`。
- **结构关联**：线索相似度向量 `u_ij = [u^P_ij, u^L_ij, u^T_ij]`
  - 人物/地点用**规范化字段的 Jaccard 重叠**；
  - 时间：区间重叠记 1，否则 `exp(-Δ(T_i,T_j)/τ)`，`τ = 7 天`；
  - 聚合：`s_str(i,j) = Σ_x β_x I_x u^x_ij / Σ_x β_x I_x`，其中 `I_x` 表示该线索类型对双方都存在且可比，权重 `β_P=0.50, β_L=0.20, β_T=0.30`；无可比线索类型的对不赋结构分。
- **稀疏增量构建**：新记忆插入时，从语义最近邻 + 人物/地点/时间线索索引中取**有界候选池（各 20）**，分别按两通道打分；语义边保留超过阈值 0.85 的、最多 6 条；结构边阈值 0.60、最多 6 条；一对记忆可仅由单通道或双通道相连，回忆时可分通道遍历再合并。

### 2.4 自适应联想回忆（Algorithm 1 / Algorithm 2）

- **混合初始召回**：从查询 `q` 抽取语义、词法、落地情节线索 `c_q`，形成三个互补召回视图
  `C_0 = C_sem ∪ C_lex ∪ C_cue`，并初始化当前证据状态 `C ← C_0`。
- **记忆锚点规划**：由**模式约束的回忆控制器** `Π_rec` 输出 `(d_r, A_r, g_r, s_r)`，即"是否继续、选择的锚点集合、缺失支持目标、可选的停止理由"。控制器决定是否需要继续回忆；若需要，则选出对查询关键或最可能通过图关联触发缺失证据的锚点，并用**目标重述 + 可选结构化线索**定义 `g_r`。
- **锚点局部扩展**：仅在**有界图邻域**内扩展
  `U_r = {m ∈ M \ C | d_G(m, A_r) ≤ h}`（`h = 2`），排除已在 `C` 中的记忆。
- **支持选择与合并**：候选对**缺失支持目标**打分——目标重述用于语义匹配，目标线索用于结构匹配；两通道 top 候选按记忆 ID 合并为轮级支持集 `S_r`；证据更新 `C ← C ∪ S_r`。
- **循环终止条件**：证据充分、无可恢复新支持、或达到轮次预算 `R = 1`。
- **证据组装**：
  - 按记忆单元 ID 去重合并，融合多来源出处信息得到 `C̄`；
  - 确定性**来源感知排序** `ρ(m) = λ_q·a(q,m) + λ_p·π(m) + λ_a·I_anc(m)`，权重固定为 `λ_q=1.25, λ_p=1.0, λ_a=0.05`；出处项 `π(m)` 的固定来源权重为语义检索 1.0、词法检索 0.75、线索查找 0.9、锚点局部扩展 0.85，排名支持为 `1/(5+rank)`；
  - 取 top-K（`K = 30`，跨 benchmark 固定不变）作为最终证据上下文，连同原查询交给答案生成器。
