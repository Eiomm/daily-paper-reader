## 摘要
大型语言模型（LLM）智能体需要对用户或组织所说和所存储的一切拥有持久、忠实的记忆，然而大多数记忆系统都固定采用单一的组织结构（事实库、向量索引或知识图谱），并因此继承其盲点。我们提出 Agent Zero Memory，一种溯源感知的长期记忆系统，它将用户的对话、文件和已连接来源提炼为三个并行的记忆系统，每个系统捕获同一历史的不同侧面：一个情节式 Memory Events 时间线，将“何时”和“什么发生了变化”作为一等公民；一个关联式实体-事件知识图谱，跨会话连接人物与项目；以及一个语义化、经策展、引用锁定的持久事实分层文档记忆（HDM）。一次检索轮次会运行意图门控（因此自包含的轮次不会增加延迟）、来源路由器，以及三个并发的智能体搜索——每个记忆系统一个——每个搜索都是在智能体控制的过滤条件下，对混合（嵌入 + 词法）搜索进行的使用工具的循环；它们有依据、带引用的答案会被整合为一个具有单一置信度的答案。我们将这种读取纪律形式化：每个被学习到的条目都是带溯源的条目，携带其来源、时间戳和证据指针；每个答案都在引用锁下读取，因此只能引用其读取器实际打开过的证据；捏造被结构性地排除，系统宁可弃权也不猜测。在两个公开基准上，该系统创下新的最优结果：LongMemEval 上达到 95.60%，LoCoMo 上达到 93.60%，分别比最强的先前系统提升 +0.73 和 +1.10 个百分点。一项跨越八个骨干 LLM 的受控研究刻画了准确率-成本-延迟前沿：准确率仅变化 3.4 个百分点，而每次查询成本变化约 30 倍；在每次查询成本最高降低 20 倍的情况下仍达到接近最优的质量，这标志着质量由记忆驱动而非模型驱动。

## Abstract
Large language model (LLM) agents need durable, faithful memory of everything a user or organization has said and stored, yet most memory systems commit to a single organizing structure (a fact store, a vector index, or a knowledge graph) and inherit its blind spots. We present Agent Zero Memory, a provenance-aware long-term memory system that distils a user's conversations, files, and connected sources into three parallel memory systems, each capturing a different facet of the same history: an episodic Memory Events timeline that makes when and what changed first-class, an associative entity-event knowledge graph that links people and projects across sessions, and a semantic, curated, citation-locked Hierarchical Documentary Memory (HDM) of durable facts. A retrieval turn runs an intent gate (so self-contained turns add no latency), a source router, and three concurrent agentic searches, one per system, each a tool-using loop over hybrid (embedding + lexical) search under agent-controlled filters; their grounded, cited answers are integrated into one answer with a single confidence. We formalize the reading discipline: every learned item is a provenanced item carrying its origin, timestamp, and evidence pointer, and every answer is read under a citation lock, so it may cite only evidence its reader actually opened; fabrication is structurally excluded and the system abstains rather than guesses. On two public benchmarks the system sets a new state of the art: 95.60% on LongMemEval and 93.60% on LoCoMo, improving over the strongest prior systems by +0.73 and +1.10 points. A controlled study across eight backbone LLMs characterizes the accuracy-cost-latency frontier: accuracy varies by only 3.4 points while per-query cost varies by ~30x, with near-state-of-the-art quality at up to 20x lower cost per query, the signature of memory-driven, rather than model-driven, quality.

# Agent Zero Memory 论文总结

## 1. 核心问题与整体含义

- **背景**：LLM 智能体需要对用户或组织"说过和存过的所有内容"拥有持久、忠实的记忆。个人/组织的知识分散在数月对话（事实被建立、修订、更正）、一次性陈述的文件，以及邮件、云盘、Wiki、代码托管等连接工具中。
- **核心问题**：现有记忆系统（MemGPT、Mem0、Zep、HippoRAG、Hindsight、ByteRover、Memobase、Mastra 等）大多**只承诺单一组织架构**——扁平事实库、向量索引或知识图谱——因此必然继承该结构的盲区：强的题目类型很强，其余很弱。
- **三条共性失败轴**（作者归纳）：
  - **写侧**：用 LLM 逐条消息做策展的系统（Mem0、Zep、Hindsight、ByteRover），摄取成本随历史线性增长且位于热路径。
  - **读侧**：查询无关读取的系统（Mastra 常驻日志、MemGPT 分页、HippoRAG 全图 PageRank、Emergence 整会话注入）为不需要的记忆付费。
  - **认知/认识论**：更新即覆盖的系统（Mem0、Memobase、Mastra 反思、Hindsight 的 newest-wins）无法区分"更正"与"被更正的前值"；且多为单用户/单项目构造，无法成为组织共享记忆。
- **整体立场**：长期记忆是**维护一个关于"已知什么"的持久、可查询、诚实模型**——不仅记录断言，还要记录其来源、支撑证据与校准的置信度；且没有任何单一表示能服务所有问题类型。因此需要多记忆并行 + 溯源感知。

## 2. 方法论

### 2.1 核心思想：三条溯源感知公设

- **(P1) 分层（Layering）**：原始源内容与蒸馏记忆分离；经策展、锁定来源的事实与推断性、可修订的经验分离——用类型纪律而非策略防止易错的推断污染地面真值。
- **(P2) 溯源与校准信念**：每个派生条目都带溯源、带置信度，且只在引用锁下读取，因此系统宁可弃权也不编造。
- **(P3) 有依据、结构感知的检索**：使用工具的读者同时按语义（稠密嵌入）和精确词项（词法匹配）在自控过滤器下检索；有可导航结构（时间线、实体图、文档层级）时，通过遍历结构而非无约束生成来产出答案。

### 2.2 形式化定义

- **三元存储**：M = (T, G_E, D)，即事件时间线、实体–事件图、文档记忆。
- **定义 1（带溯源条目）**：条目对 (x, π(x))，其中 π(x) = ⟨o(x), t(x), ev(x)⟩，o(x) ∈ {scan, infer, doc, dialogue, manual} 为来源类型，t(x) 为不可变创建时间戳，ev(x) 为可（经中间摘要记录）解析到原始工件集 A 的证据指针。
- **定义 2（引用锁答案）**：设 O ⊆ M 为读者在本次情节中**实际打开过**的条目集合，则答案 (a, C, κ) 是引用锁定的，当且仅当 C ⊆ O 且 a 的每个原子主张都被 C 中某条目支撑；无法组装这样的 C 时必须返回 a = ⊥（弃权）。
- 引用锁是**由构造强制**的语法纪律（读者接口不存在引用未打开材料的通道），但带来语义后果：捏造被**结构性排除**而非仅被劝阻。

### 2.3 Memory Build：四阶段流水线 → 三套并行记忆

- **(1) 预处理与分类**：将原始源规范化为干净文本并打标签（chats / files / agent sessions），后续按类型分别切分与蒸馏。
- **(2) 索引**：为所有内容同时建立嵌入索引与词法检索索引（按意义或按精确/模糊词项均可找到）。
- **(3) 抽取**：由 LLM 分析蒸馏出两件产物——**Memory Events 时间线**与**分层文档记忆 HDM**。
- **(4) 连接**：智能体过程在事件与 HDM 节点上构建实体–事件本体图。
- **三套记忆的分工**：
  - **Memory Events（情节/语义时间线）**：每个事件含简明描述与"何时发生、如何展开"的时间线；事件是召回的首选单位，需细节时才打开底层原始对话/文件；跨源合并时间线支撑"何时""什么变了""来自哪个源"。
  - **Ontology Graph（实体与关系）**：把人物、团队、项目相互连接并与涉及事件相连，将扁平事件流变成可导航图，支撑跨会话多跳问题。
  - **HDM（语义、经策展、引用锁定核心）**：针对必须站得住的事实（用户画像、稳定偏好、关心的人与项目），分六类（profile、preferences、entities、milestones、cases、patterns），每条按 **L0 一行摘要 / L1 概览 / L2 全文** 三级书写，读者先在廉价摘要上定位、必要时才打开全文，且全文打开有硬上限。HDM 由用户自撰笔记**确定性映射**构建，而非事实抽取，因此不会凭空发明或漂移。

### 2.4 Memory Injection：三路并发智能体搜索（算法流程）

- **步骤 1**：**意图门控** g（小型快速分类器）判断当前轮次是否需要记忆、需要哪一类；自包含轮次直接通过，**不增加延迟**。
- **步骤 2**：**来源路由器**将检索限制在最可能含相关证据的源桶子集（连接器、各智能体对话历史、文档记忆）。
- **步骤 3**：**三个并发智能体搜索**，每套记忆一个。每个搜索本身是一个使用工具的循环：(i) 按意义（嵌入）与按精确词项（词法）双向查询；(ii) 自控丰富过滤器（时间窗、标签、来源、说话人/类型）；(iii) 按需打开原始块；最终产出各自引用锁定的部分答案 (a_m, C_m, κ_m)。
- **重排**：相关性重排按匹配分重排候选，但当读者请求时间序时**故意跳过**，保证"最新/自 T 以来"查询保持时间序。
- **步骤 4（Integrate）**：合并三份部分答案，取 C = ∪_m C_m 与聚合置信度，返回单一带引用答案，并**继承其组成部分的引用锁**。

### 2.5 三类记忆与持续学习

| 记忆种类 | 来源 | 生命周期 |
|---|---|---|
| 事实性（Factual） | 直接从对话/文件/来源读取 | 持久；源变更时重新同步 |
| 经验性（Experiential） | 推断、从用户工作方式中学到 | 持久；持续精炼（不清楚时可询问用户） |
| 工作记忆（Working） | 当前对话、指令、任务上下文 | 会话绑定；有用部分被提升 |

- **持续学习循环**：任务结束时把所学总结、归档为与周边事件相关的经验性记忆，在后续相似任务出现时浮现；组织部署中记忆共享，一个智能体学到的教训可被所有智能体使用。

### 2.6 工程实现

- 单一 PostgreSQL 实例承载记忆存储与两类索引；事件、图节点/边、HDM 条目关系化存储并保留溯源。
- 稠密检索用 **pgvector**，3072 维嵌入、余弦相似度；词法检索用 **BM25** 排序 + 模糊（近似）字符串匹配。
- 每个智能体搜索从每通道取 top-K，用 **RRF（reciprocal rank fusion，k=60）** 融合，之后可选重排。

## 3. 实验设计

## 6. 主要结论与发现

- **新的最优结果**：LongMemEval **95.60%**（超次优 Mastra 94.87% 达 **+0.73** 分，远超 Zep 71.20%）；LoCoMo **93.60%**（超 Mem0 92.50%、ByteRover 2.0 92.20%，分别 **+1.10**、+1.40 分）。
- **质量由记忆驱动而非模型驱动**：八个骨干准确率仅相差 **3.4 分**（92.20%–95.60%），而每查询成本相差 **约 30×**。近最优质量可在**低至 1/20 成本**下获得（deepseek-v4-pro 92.20% vs gpt-5.5 95.60%，$0.001768 vs $0.034788）。
- **三轴权衡无单一支配者**：gpt-5.5 准确率最高；glm5.2fast 延迟最低（中位 6.16 s，93.00%，距最高仅 2.6 分）；deepseek-v4-pro 成本最低。成本效率最高者比最准确者每美元多约 19× 的准确率，仅让出 3.4 分。
- **成本不等于 token 量**：缓存输入占比 43.6%（gpt-5.5）到 88.2%（deepseek-v4-pro）；opus4.8 与 sonnet5 处理 token 最多却非最贵，正因大部分被缓存。低基础价 + 高缓存折扣才造就成本领先者。
- **混合检索通道互补**：仅嵌入 −1.20 分（95.20→94.00），grep-only −1.60，仅词法 −1.80；但**每个受限变体仍超过最强外部基线**，说明结构化、带溯源的存储与智能体读取纪律承载了大部分质量，混合检索贡献的是最后那部分登顶边际。
- **设计对基准失败模式的针对性**：时间线对应时间/知识更新题，实体图对应跨会话多跳题，引用锁定 HDM 对应稳定画像/偏好题且在缺证据时弃权。

## 7. 优点

- **问题诊断有穿透力**：以"写侧 / 读侧 / 认识论"三条失败轴统一剖析现有各家记忆系统，并在表 1 沿记忆组织、更新语义、溯源、读成本随历史增长方式、作用域五个维度逐项对比，动机推导扎实。
- **形式化贡献清晰**：把"带溯源条目"（定义 1）与"引用锁答案"（定义 2）写成可检验的读取纪律，并明确区分"语法上由构造强制"与"语义上排除捏造"，是少见把可信性做成结构性保证而非提示词约束的设计。
- **非破坏性更新语义**：更新是新增带时间戳的信念并保留证据，被取代的值仍可区分——这正对准 LongMemEval 知识更新与 LoCoMo 时间题的核心难点。
- **读成本按查询而定**：意图门控让自包含轮次零延迟直通，路由 + 各库 top-k 检索避免了常驻日志或全图 PageRank 式的查询无关开销。
- **HDM 用确定性映射而非抽取**：对必须可靠的事实避免 LLM 抽取漂移，并用 L0→L1→L2 分级 + 打开上限控制成本，设计取舍明确。
- **工程落地考量周到**：PostgreSQL + pgvector + BM25 + RRF 的朴素栈、后台构建、

- **工程落地考量周到**：PostgreSQL + pgvector + BM25 + RRF 的朴素栈、后台构建、源变更时的重新同步、会话绑定工作记忆向持久记忆的提升路径，均以"可运维、可增量"为目标，避免了为追求架构新颖性而引入难以维护的组件。
- **成本透明度高**：同时报告美元成本与 token 数（含缓存输入/完成 token 拆分），使结论可随各厂商定价变动被重新计算，而不是锁死在某一时刻的价格表上。
- **对"弃权"的正视**：把"答案从未被陈述时拒答"作为一等公民纳入评测，并让引用锁在无法组装证据时强制返回 ⊥，这在以"答对率"为唯一导向的记忆文献中较为少见。

## 8. 缺点与局限

- **组件贡献未被拆解**：论文的核心主张是"三套并行记忆 + 溯源纪律"优于单一表示，但**从未单独度量**时间线、实体图、HDM 各自以及意图门控、来源路由器的边际增益。读者无法判断 95.60% 中哪一部分来自架构、哪一部分来自骨干、哪一部分来自检索融合，作者亦将组件级消融列为未来工作——这使最强的方法论主张停留在"整体有效"而非"各部件必要"。
- **跨系统对比的可比性存疑**：竞品数字取自各自公开报告，评审模型、提示词模板、检索预算、上下文窗口配置均不统一。作者虽已明确提示应读作"在最强已报告结果中的定位"，但 +0.73 / +1.10 这类小差距在非受控设置下不足以支撑"显著超越"的强断言。
- **统计稳健性缺失**：全部准确率为单次运行，无置信区间、无多次采样方差、无显著性检验。在 500 题基准上 0.73 分的差距完全可能落在运行噪声范围内，而论文未提供任何证据排除这一点。
- **无第三方复现与真实部署验证**：结果全部来自作者自评 harness；尽管反复强调"组织共享记忆""多智能体共享教训"，评测却仅限于两个公开的**英文、单人、对话式**基准，组织级场景（多用户权限、跨项目隔离、冲突归属、共享记忆的污染风险）完全未被检验。
- **写侧成本未同等审视**：论文以"摄取成本随历史线性增长且位于热路径"批评 Mem0/Zep 等，但自身并未报告 Memory Build（分类、抽取、建图、HDM 构建）的离线成本、延迟与 token 消耗，只在读侧报告了每查询成本。四阶段流水线同样需要为每条消息调用 LLM 抽取事件与建图，其写侧开销是否真的更低，缺乏数据支撑。
- **读侧延迟数字不完整**：仅报告中位墙钟延迟，未给 P95/P99 尾延迟，也未报告意图门控分类器本身的推理开销与误判率（漏判会导致该召回时未召回，误判会导致无谓的检索与延迟）。
- **引用锁的代价未被量化**：引用锁在结构上排除捏造，但也可能因"未打开即不可引用"而**系统性地过度弃权**或漏答（读者未检索到本可检索的证据）。论文未报告弃权率、误弃权率，也未分析该纪律对召回率的负面影响。
- **骨干命名与可验证性**：所列骨干名称（gpt-5.5、opus4.8、deepseek-v4-pro 等）与当前公开模型谱系不符，若为匿名化或未来版本，读者无法独立核对，削弱了成本/延迟结论的可验证性。
- **成本结论时效性强**：成本分析完全建立在"各提供商公开列表价 + 缓存折扣"之上，而缓存定价与折扣策略是厂商最易变动的一环，"每美分准确率点数从 18.0 到 521"的排序随时可能被一次调价改写。
- **分类体系与门控的刚性**：HDM 的六类（profile/preferences/entities/milestones/cases/patterns）与"事实性/经验性/工作"三分法均为人工先验；论文未讨论当领域不匹配（如医疗、法律、科研）时该分类是否仍成立，也未给分类边界的判定规则。

## 9. 总体评价与启示

- **定位**：这是一篇**系统设计 + 工程实证**型论文，而非算法创新论文。其真正贡献不在某个新模型或新损失，而在于把"长期记忆"重新定义为一个**关于已知内容的、可查询且诚实的模型**，并用"分层 / 溯源与校准 / 结构感知检索"三条公设把该定义落成可实现的读取纪律。
- **最具迁移价值的观点**：
  - **可信性可以做成结构性保证**：把"只能引用实际打开过的条目"写进读者接口，使捏造在语法层面不可能发生，而非依赖提示词劝阻。这一思路可推广到 RAG、代码助手、审计型智能体等一切"输出必须可溯源"的场景。
  - **非破坏性更新**：以"新增带时间戳的信念 + 保留证据"替代"覆盖式更新"，使被更正的前值仍可区分。这对知识更新、审计、合规类应用是刚需，也直接对应基准中最难的题型。
  - **读成本应与查询相关**：意图门控 + 来源路由 + 每库 top-k，把"为不需要的记忆付费"降到接近零，与常驻全量日志、全图 PageRank 形成鲜明对比。
  - **质量的上限由记忆架构而非模型决定**：8 个骨干仅差 3.4 分而成本差约 30×，暗示在记忆类任务上，**投资于记忆表示与读取纪律的边际回报远高于换更强的模型**——这是对"堆模型即堆效果"直觉的一次有力反驳。
- **方法论上的遗憾**：论证强度与主张强度不匹配。作者提出的架构性主张（多记忆并行优于单一表示）本可用受控消融直接证实，却只提供了整体端到端结果；跨系统对比又受限于非受控设置。结果是：**结论方向可信，但幅度与归因尚不牢固**。
- **对后续工作的直接建议**：(1) 补齐三套记忆与门控的逐一消融及门控开关实验；(2) 报告多次运行的方差与置信区间，尤其在 0.7–1.4 分的小差距上；(3) 公开 Memory Build 的写侧成本，与所批评的系统做同口径对比；(4) 引入真实组织场景或多用户权限基准，检验"共享记忆"的实际收益与污染风险；(5) 报告弃权率与误弃权率，量化引用锁的代价。
- **一句话总结**：论文用"分层 + 溯源 + 结构感知检索"把长期记忆从"检索问题"提升为"认识论问题"，在公开基准上取得领先并揭示了"记忆驱动而非模型驱动"的质量–成本规律；其设计思想的说服力目前强于其经验证据的严密程度。
