## 摘要
随着个人智能体的广泛采用，用户在长期交互过程中会产生海量异构数据。将这些数据用作长期记忆有助于降低 token 开销并提供个性化体验。然而，现有记忆系统面临两个主要限制：它们依赖单一存储范式，导致多维数据碎片化；并且缺乏细粒度的数据溯源来消解长期事实冲突，从而加剧 LLM 幻觉。在本演示中，我们介绍 PolyMemDB，一个专为管理智能体记忆而设计的新系统。PolyMemDB 采用多语言存储架构，旨在追踪和管理各种记忆类型，包括图、向量、概率和时空数据。为确保事实一致性并减少幻觉，它具备一个概率推理引擎，将时间衰减与半环聚合相结合，解决长期事实冲突，提供详细的数据溯源，并使用户能够透明地追踪推理链。

## Abstract
With the widespread adoption of personal intelligent agents, users generate massive, heterogeneous data during long-term interactions. Leveraging this data as long-term memory helps reduce token overhead and deliver personalized experiences. However, existing memory systems face two primary limitations: they rely on single-storage paradigms that fragment multi-dimensional data, and they lack fine-grained data provenance to resolve long-term factual conflicts, thereby worsening LLM hallucinations.   In this demonstration, we introduce PolyMemDB, a novel system tailored for managing agent memory. PolyMemDB has a polyglot storage architecture designed to track and manage various memory types, including graph, vector, probability and spatial-temporal data. To ensure factual consistency and reduce hallucinations, it features a probabilistic inference engine that integrates temporal decay with semiring aggregation, resolving long-term factual conflicts, providing detailed data provenance, and enabling users to trace reasoning chains transparently.

## 2. 方法论

### 2.1 总体架构

PolyMemDB 的工作流分为三阶段：

- **记忆摄取与索引（Memory Ingestion & Indexing）**
  - 利用 LLM 和 VLM 将输入数据分解为原子事实。
  - 执行实体对齐、共指消解、省略恢复、命名实体抽取、事实归一化和置信度估计。
- **多存储层（Polyglot Storage Layer）**
  - **Neo4j**：存储实体、属性及其长期演化轨迹，构成关系图。
  - **ProvSQL**：存储事件置信度，支持概率数据库推理。
  - **MobilityDB**：管理复杂时空约束，支持动态时间窗口与地理多边形联合过滤。
  - **ChromaDB**：存储嵌入向量。
  - **对象存储**：保存原始多模态内容。
- **推理与级联问答（Inference & Cascaded QA）**
  - 采用自顶向下、三层联邦检索机制：
    - **Tier 1 Graph QA**：优先低延迟子图遍历，联合概率数据库和时空索引进行规则过滤与逻辑推理。
    - **Tier 2 Dense Retrieval**：若 Tier 1 无答案，则用查询嵌入在向量库中做 Top-k 语义检索。
    - **Tier 3 Multi-modal Retrieval**：若证据仍不足，直接检索原始多模态数据片段。
  - 最终生成回答。

### 2.2 记忆图形式化与动态更新

- 记忆图定义为 \(G=(V,E,\alpha)\)：
  - \(V\)：异构实体集合，如 PERSON、CONCEPT 等。
  - \(E \subseteq V \times L \times V\)：有向关系边。
  - \(\alpha\)：属性标注函数。
- 单条事实定义为 \(f_i = \langle \rho_i, c_i, t_i \rangle\)：
  - \(\rho_i \in \{+,-\}\)：证据情感极性。
  - \(c_i \in [0,1]\)：LLM 赋予的初始置信度。
  - \(t_i\)：事实观察时间戳。
- 插入新事实前，系统通过语义相似度检索 Top-k 局部子图作为上下文，由智能体自主决定创建或更新节点/边，以提升实体对齐准确率。

### 2.3 数据溯源与证据链

- 对图中任意三元组 \(e=(u,l,v)\)，系统不采用简单状态覆盖，而是在边属性上维护历史观察序列：
  - \(F=(f_1,f_2,\dots,f_T)\)，满足 \(t_1 \le t_2 \le \dots \le t_T\)。
- 该机制保留不同时间点的证据，为后续概率推理和推理链追溯提供基础。

### 2.4 基于时间衰减的概率推理

- 引入指数衰减因子 \(\lambda \in (0,1]\)。
- 对序列中时间距离索引为 \(\Delta_i = T-i\) 的事实，其动态权重为：
  - \(w_i = c_i \cdot \lambda^{T-i}\)
- 基于容斥原理，将证据序列划分为正证据集 \(F^+\) 和负证据集 \(F^-\)，分别计算累计联合置信度：
  - \(P^+ = 1 - \prod_{f_i \in F^+}(1-w_i)\)
  - \(P^- = 1 - \prod_{f_j \in F^-}(1-w_j)\)
- 进一步计算四种中间认知状态：
  - 正向驱动：\(S_{action}=P^+(1-P^-)\)
  - 负向抑制：\(S_{inaction}=P^-(1-P^+)\)
  - 证据冲突：\(S_{conflict}=P^+P^-\)
  - 证据缺失：\(S_{ignorance}=(1-P^+)(1-P^-)\)
- 综合净证据可靠性得分 \(R \in [-1,1]\)：
  - \(R=(S_{action}-S_{inaction}) \cdot (1-S_{conflict}-S_{ignorance})\)
- 解释：
  - 基础项 \(S_{action}-S_{inaction}\) 决定方向真实性，支持事实为正，反驳为负。
  - 乘子 \(1-S_{conflict}-S_{ignorance}\) 是动态惩罚项，当存在明显事实争议或证据不足时降低净可靠性。
  - 当 \(R \approx 0\) 时，可通过最大中间状态区分低分来源是“事实矛盾”还是“证据真空”。
- 在 QA 阶段，系统将 \(R\) 和分解分布作为量化参考提供给 LLM，避免二元幻觉，生成有溯源依据的细致回答。

### 2.5 与已有系统的概念对比

- **MemForest**：关注高效时间写入，树结构组织时间信息，仅沿特定路径更新。
- **HyperMem**：三层超图模型，主题、片段、事实，超边捕获离散记忆片段依赖。
- **MRAgent**：构建 “Cue-Tag-Content” 图，依赖主动重构机制，让 LLM 迭代探索和剪枝。
- **PolyMemDB 差异**：
  - 放弃单一存储范式，采用多存储架构。
  - 不仅用 Neo4j 维护实体拓扑，还将时空约束下推到 MobilityDB。
  - 扩展概率数据库半环推理，在边属性上附加历史观察序列，通过概率推理和时间衰减计算正向驱动、负向抑制、证据冲突分布。
