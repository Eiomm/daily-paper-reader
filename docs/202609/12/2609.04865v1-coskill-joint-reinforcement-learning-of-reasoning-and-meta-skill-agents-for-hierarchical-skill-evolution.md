## 摘要
技能库通过使大语言模型（LLM）智能体能够复用过程性知识，提升了智能体强化学习（RL）的样本效率。然而，现有范式存在结构性缺陷：它们要么将技能演化与策略优化解耦，要么将元技能实例化为固定工作流。二者都将技能视为被管理的被动对象，限制了技能的灵活演化及其与推理智能体的协同适应。为解决这些局限，我们提出 CoSkill，一个统一的多智能体 RL 框架，它将静态元技能工作流重构为可学习的元技能智能体，并在分层技能库上将其与推理智能体联合训练。通过将推理智能体和元技能智能体建模为共享单一骨干网络的协作团队，CoSkill 实现了端到端的协同适应：推理智能体以检索到的任务技能以及从其子集中选出的步骤技能为条件进行动作，而其任务表现则指导元技能智能体改进这些步骤技能。在 ALFWorld 和 WebShop 上的实验表明，CoSkill 显著优于先前基于技能的基线和 RL 基线，分别达到 98.4% 和 90.6% 的成功率（+3.5 和 +6.2 个百分点）。如图 1 所示，CoSkill 在早期样本效率、渐近性能和实际运行时间效率方面均表现更优。我们的代码见 https://github.com/jinyuan-cookie/CoSkill。

## Abstract
Skill libraries improve the sample efficiency of agentic reinforcement learning (RL) by enabling large language model (LLM) agents to reuse procedural knowledge. Yet existing paradigms exhibit structural shortcomings: they either decouple skill evolution from policy optimization or instantiate meta-skills as fixed workflows. Both treat skills as passive objects to be managed, limiting the flexible evolution of skills and their co-adaptation with the reasoning agent. To address the limitations, we propose CoSkill, a unified multi-agent RL framework that recasts the static meta-skill workflow as a learnable Meta-Skill Agent and jointly trains it with a Reasoning Agent over a hierarchical skill library. By modeling the Reasoning and Meta-Skill Agents as a cooperative team sharing a single backbone, CoSkill enables end-to-end co-adaptation: the Reasoning Agent conditions its actions on a retrieved task skill and step skills selected from its child set, while its task performance guides the Meta-Skill Agent in refining those step skills. Experiments on ALFWorld and WebShop show that CoSkill substantially outperforms prior skill-based and RL baselines, achieving success rates of 98.4% and 90.6%, respectively (+3.5 and +6.2 pp). As shown in Figure 1, CoSkill achieves superior early-stage sample efficiency, asymptotic performance, and wall-clock efficiency. Our code is available at https://github.com/jinyuan-cookie/CoSkill.

## 1. 核心问题与整体含义

- **研究背景**：技能库让 LLM 智能体复用过程性知识，从而提升智能体强化学习（agentic RL）的样本效率，是长时程任务求解的重要范式。
- **核心痛点**：现有技能库方法存在结构性缺陷，技能演化难以与推理策略协调。论文归纳出三种范式，各有局限：
  - **(a) 外部编排的技能演化**（SkillRL、D2Skill、ReSkill、Trace2Skill）：技能库被当作独立知识库，生成/修订/维护交给外部 LLM 或手工规则。技能演化位于策略学习目标之外，库易过时、冗余，并与演化的推理策略错配。
  - **(b) RL 优化的技能库管理**（SAGE、ARISE、Skill1）：用下游奖励优化技能生命周期决策，但优化粗粒度——技能被视为原子条目，内部流程未被优化，有用但不完美的技能可能被弃用而非精修。
  - **(c) 元技能驱动的技能优化**（SkillOpt、EvoSkill、SkillEvolver、MetaSkill-Evolve）：用执行反馈优化单个技能流程，但依赖预定义元技能程序（rubric prompt、SKILL.md、多智能体工作流），且通常冻结推理智能体，固定更新规则无法与演化策略协同适应。
- **共同症结**：三者都把技能视为"被管理的被动对象"，导致技能—策略错配（skill–policy mismatch）。
- **核心洞见与整体含义**：将元技能公式化为 **RL 训练的可学习智能体**而非固定工作流，使其更新策略能与推理策略协同演化；由此把技能演化从"外部编排过程"重构为"应与推理共同优化的可学习过程"。

## 2. 方法论

### 2.1 总体框架
- CoSkill 是一个统一的多智能体 RL 框架，把 **Reasoning Agent（推理智能体）** 与 **Meta-Skill Agent（元技能智能体）** 建模为**共享单一 LLM 骨干**的协作团队，在分层技能库上联合训练，实现端到端协同适应。
- 推理智能体以检索到的任务技能 + 步骤技能为条件行动；其任务表现通过 Post-Edit Skill Verification 转化为结果对齐的反馈，指导元技能智能体精修步骤技能。

### 2.2 分层技能库
- 库结构：`B = {B_k}_{k=1..K}`，每个 bundle 为 `B_k = (s^task_k, S^step_k)`：任务技能提供 episode 级全局指导，其子集 `S^step_k` 提供面向中间观测的局部流程。
- 两级检索（式 4）：先按任务指令检索任务技能 `k* = argmax_k sim(f(x), f(q_k))`，再**仅在该任务技能的子树内**检索步骤技能 `j*_t = argmax_{j∈S^step_k*} sim(f(o_t), f(o_{k*,j}))`。任务技能固定候选子树，保证全局指导稳定、局部决策自适应。
- 上下文 = 固定的 `Z^task` + 观测依赖的 `Z^step_t`。
- 离线初始化：先用外部 LLM 采集轨迹并归纳层级 bundle，再做 grounding 校验与去重。ALFWorld 初始库含 300 个任务技能 + 1625 个步骤技能；WebShop 含 300 + 1406。

### 2.3 共享参数多智能体半马尔可夫决策过程（MSMDP）
- 形式化：`M = <S, Ω, A, P, R, γ, T>`，T 刻画两个角色不同的时间尺度。
- **全局状态** `g_ℓ = (x, ρ_ℓ, H_ℓ, B, B̃_ℓ, Z_ℓ)` 作为共享黑板（ρ 为活跃角色，H 为交互与验证轨迹，B̃ 为私有编辑包，Z 为待定编辑）；两个智能体都不直接观测全局状态，只接收角色特定的投影。
- **角色特定观测**：
  - 推理：`u^R_t = O_R((x,o_t) ∪ h_t ∪ (Z^task, Z^step_t))`。
  - 元技能：`u^S_t = O_S(Select_S(u^R_t) ∪ a_t ∪ (r_t, e_t, o_{t+1}))`，即 `(o_t, Z^step_t, a_t, r_t, e_t, o_{t+1}, h_t)`——推理动作本身成为诊断与优化技能的更高层观测。
- **异构动作空间**：两者共享策略 `π_θ` 与 token 空间，由角色 prompt 引导。元技能语义动作限制为 `A^S = {INSERT, UPDATE, DELETE, KEEP}`（INSERT 在所选任务技能下新增候选，UPDATE 替换活跃流程，DELETE 删除，KEEP 不变）。
- **顺序交互与延迟技能更新**：baseline 尝试（m=0）中 `Z^task` 固定、逐步检索 `Z^step_t`；所有编辑提案**暂存至该尝试结束**，再应用到检索 bundle 的私有副本 `B̃_i = Apply(Copy(B_{k*_i}), z_{i,1:L_i})`，以保持 baseline 轨迹不被污染。

### 2.4 Post-Edit Skill Verification Reward
- baseline 尝试得回报 `R^(0)_i`；随后重置同一任务，用私有编辑包运行 M 次验证尝试得 `R^(1..M)_i`。
- 技能编辑奖励为**平均编辑后改进**：`Δ^skill_i = (1/M) Σ_{m=1..M} R^(m)_i − R^(0)_i`。
- 设计要点：减去 baseline 以控制任务难度；对 M 次验证取平均以降低 rollout 方差；该延迟 episode 级奖励只赋给编辑序列，baseline 推理动作保留各自的环境回报。
- 私有包仅在"含有效非平凡编辑 且 验证成功率高于 baseline"时成为提升候选；每个任务组内排序，只提升 top-`K_prom` 个 bundle 版本，并保留原始 bundle 以维护 lineage，从而限制库增长。
