## 摘要
大型语言模型（LLMs）正越来越多地被部署为长时程对话智能体，这促使人们对记忆系统的兴趣日益增长。然而，现有基准主要通过问答式探测来评估记忆，而非在实际对话使用场景中进行评估。我们提出了 LOCOMO-CONV，一个从 LoCoMo 衍生的对话记忆基准，包含四种查询风格：对话式、隐式、反事实和组合式。我们在五个代表性记忆系统上评估了检索召回率和端到端响应质量。实验表明，对话式框架暴露出被问答基准忽视的大量检索缺口，尤其是在隐式和组合查询上；多面查询重写能缩小原始轮次记忆的缺口，但对抽象式记忆无效。我们进一步发现，强检索并不能完全转化为响应质量，并且隐式查询表现出静默锚定：记忆改善了上下文锚定，却没有显式呈现金标准事实。这些结果指向基于推理的记忆细化是一个有前景的方向，并且我们发布了辅助的 supportive_memory 标注，用以捕捉超出原始金标准证据的对话有用上下文。

## Abstract
Large language models (LLMs) are increas- ingly deployed as long-horizon conversational agents, motivating growing interest in mem- ory systems. However, existing benchmarks primarily evaluate memory through QA-style probing rather than in-situ conversational usage. We introduce LOCOMO-CONV, a conversa- tional memory benchmark derived from Lo- CoMo with four query styles: dialog, implicit, counterfactual, and composed. Across five rep- resentative memory systems, we evaluate both retrieval recall and end-to-end response qual- ity. Our experiments show that conversational framing exposes substantial retrieval gaps over- looked by QA benchmarks, especially on im- plicit and composed queries, which multi-facet query rewriting narrows for raw-turn mem- ory but not abstractive memory. We further find that strong retrieval does not fully trans- late into response quality, and that implicit queries exhibit silent grounding, where mem- ory improves contextual grounding without ex- plicitly surfacing the gold fact. These results point to reasoning-based memory elaboration as a promising direction, and we release aux- iliary supportive_memory annotations captur- ing conversationally useful context beyond the original gold evidence.

## 1. 核心问题与整体含义

- **研究动机**：LLM 日益被部署为跨会话的长时程对话智能体，记忆系统成为核心需求——不仅要存储过往交互，还要在未来对话需要时正确检索并运用。
- **核心痛点**：现有记忆基准（如 LoCoMo、LongMemEval、MemoryAgentBench）几乎都通过**显式问答式探测**（第三人称 QA 匹配、多选题、约束检查等）来评估记忆，而非评估记忆在**真实对话中的实际调用**。
- **关键问题**：用户在日常对话中往往**不直接提问**，而是通过情境、感受、计划或错误前提间接唤起记忆；现有基准无法回答记忆系统能否支撑这种自然交互。
- **整体含义**：论文提出 **LOCOMO-CONV**，把记忆评估从"问答探测"推进到"对话式调用"，揭示被 QA 基准掩盖的检索失败，并指出记忆系统设计应从**有损压缩**转向**基于推理的语义细化**。

## 2. 方法论

### 2.1 核心思想

- 固定 LoCoMo 的原始记忆与金标证据，**仅改写用户侧查询框架**，构造四种第一人称对话查询风格，从而隔离"对话框架"对记忆调用的影响。

### 2.2 四种查询风格

- **Dialog（对话式）**：将原始 QA 改写为直接的第一人称对话询问（如"你还记得我跟你说过我妈的爱好吗？"），事实目标不变。
- **Implicit（隐式）**：情境化话语，**不含显式提问**，要求助手主动推断并浮现相关记忆（如为妈妈挑生日礼物时想不起她的爱好）。
- **Counterfactual（反事实）**：包含**错误前提**，助手需识别并用记忆纠正（如把妈妈的爱好误说成园艺和编织）。
- **Composed（组合式）**：需要跨多个源 QA 与证据片段进行**多事实综合**。

### 2.3 组合式查询的构造算法

- 对每个 QA 实例 $q$，令 $E(q)$ 为其金标证据 dia_id 集合。
- 枚举同一样本内的 QA 对 $(q_i, q_j)$，满足三个条件才保留为候选簇：
  1. **证据重叠**：$E(q_i) \cap E(q_j) \neq \emptyset$；
  2. **证据不完全相同**：$E(q_i) \neq E(q_j)$；
  3. **合并证据非平凡**：$|E(q_i) \cup E(q_j)| \geq 2$。
- 共得到 **1,069 个组合簇**（每段对话 36–198 个）。
- 组合金标答案定义为成员 QA 原子答案的并集，金标证据为 dia_id 并集；使用**连续原子事实覆盖率**而非二值正确性评分。

### 2.4 评估方法

- **检索召回**：比较 top-K 检索记忆与金标 dia_id，公式为 $|retrieved \cap gold| / |gold|$；抽象式系统额外通过 metadata 匹配 dia_id。
- **响应质量**（风格特定 LLM 评判）：
  - Dialog / Implicit：3 级 `fact_used`（1.0 完整 / 0.5 部分 / 0.0 缺失或矛盾）；
  - Counterfactual：3 类 unaware / hedge / corrected → 0 / 0.5 / 1；
  - Composed：原子事实覆盖率（逐事实独立判断）。
- **辅助技术**：
  - **Multi-facet query rewriting**：用 GPT-5.4-mini 将查询分解为 3–5 个互补切面，独立检索后用 **RRF（Reciprocal Rank Fusion）** 融合排序。
  - **Response CoT**：生成回答前先显式选择相关记忆，检索结果不变，仅改答案侧提示。

## 6. 主要结论与发现

1. **对话框架暴露 QA 基准掩盖的检索缺口**：隐式与组合查询在所有系统上都是最难的；隐式查询召回显著低于直接对话查询。
2. **不同记忆范式各有擅长**：AnchorMem 在事实检索型风格（dialog 0.659、counterfactual 0.639）最佳；抽象式系统（mem0 0.456 / Memora 0.445 implicit；0.374 / 0.387 composed）在语义宽泛风格上更优。
3. **多面查询改写缩小检索缺口**：对 AnchorMem 提升最大（implicit +15.6pt、composed +14.7pt），但对抽象式记忆几乎无效甚至有害（mem0 dialog 下降），说明查询改写与记忆细化作用于**同一语义欠指定问题**的不同阶段。
4. **强检索 ≠ 好响应**：mem0 检索强但生成弱（dialog fact_used 仅 0.366 vs AnchorMem 0.598）；Memora 则能把检索优势转化为最佳 implicit/composed 响应。
5. **静默 grounding（silent grounding）**：在 332 条 Oracle 仍得 `fact_used=0.0` 的隐式查询中，Oracle 记忆在 faithfulness（+55.1pt）和 engagement（+31.0pt）上显著优于 no-memory 与 random，说明记忆改善了上下文锚定却不显式呈现金标事实，**严格事实召回指标低估了记忆价值**。
6. **CoT 选择逼近 Oracle 质量**：CoT 在 dialog/implicit/composed 上提升响应，但在 **counterfactual 上显著有害**——模型先复述用户错误前提，把记忆用来"调和"而非"纠正"；推理步骤单独使纠正率下降 0.16–0.19。
7. **压缩 vs 细化**：抽象本身无害，**有损压缩**才是有害的——压缩保留语义匹配信息却丢弃响应锚定所需的具体细节；未来记忆系统应偏向**基于推理的语义细化**而非有损压缩。
8. **发布 supportive_memory 标注**：捕捉超出原始金标证据的、对话上有用的支持性上下文。

## 7. 优点

- **评估范式创新**：首次系统性地把记忆评估从第三人称 QA 探测转向第一人称、自由形式的对话式调用，四种查询风格设计贴合真实使用场景。
- **统一双维度评估框架**：同时评测检索召回与端到端响应质量，可系统比较抽取式与抽象式记忆系统。
- **分析深入且有洞察**：静默 grounding、压缩 vs 细化、CoT 损害反事实纠正等发现具有设计指导意义，而非停留在排行榜数字。
- **严谨性设计**：跨评判模型一致性验证（Cohen κ 0.68–0.80）、人工标注验证、索引重建与答案采样的方差分析（std ≤ 0.011）。
- **可扩展性**：构造流程与来源无关，可套用到任意带 QA 式证据标注的对话池。
- **资源开放**：发布 GitHub 仓库与 supportive_memory 辅助标注，利于后续研究。

## 8. 不足与局限

- **基准规模小**：仅基于 10 段 LoCoMo 对话，相对真实长时程交互偏小。
- **LLM 生成偏差**：查询改写与 supportive_memory 标注均由 LLM 管线生成，可能继承模型特定偏差；人工验证仅覆盖每风格 40 条样本，非全集。
- **模型覆盖有限**：仅使用单一开源权重答案模型（gemma-4-31B-it）和一个主评判家族，跨评判与人工验证仅在子集上进行。
- **压缩 vs 细化对比非受控**：mem0 与 Memora 在记忆构建机制之外还存在其他设计差异（如 Memora 的 cue-anchor 设计），不能作为压缩 vs 细化的决定性结论。
- **人为调参**：Memora 默认检索阈值（0.4）被关闭以适配对话查询，可能影响其真实表现的代表性。
- **应用限制**：反事实风格中 21/40 前提被评"至少可现实陈述"，修正准确率随前提可信度下降（52.6% → 38.1%），实际部署中的纠错鲁棒性仍存疑。
