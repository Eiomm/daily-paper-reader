## 摘要
流式语言模型的方法常与长上下文和记忆系统一同讨论，尽管它们解决的是不同问题。注意力汇可以在无限长的流上稳定自回归生成，而模型仍然无法使用已离开其近期词元缓存的内容。我们认为，这种区别应在系统声明和评估中得到明确体现。我们引入三种视界：稳定视界，在该视界内预测行为保持良好；访问视界，在该视界内过去内容仍能因果性地影响输出；以及效用视界，在该视界内任务仍保持可接受的性能。我们构造性地表明，稳定视界可以是无限的，而访问视界和效用视界是有限的。随后我们提出 ThreeH，一种在共同的状态与计算预算下度量全部三种视界的评估契约。将该框架应用于注意力汇流式方法，可阐明其优势——恒定内存、稳定生成——同时不把锚词元当作语义记忆。该框架揭示了缓存策略、循环状态、检索和外部记忆各自的作用。在 128K 词元流、延迟绑定召回和延迟决策上的实验表明，注意力汇保留了局部建模能力，但不能保留活动缓存之外的内容；循环状态和检索状态扩展了语义视界。

## Abstract
Methods for streaming language models are often discussed alongside long-context and memory systems, although they solve different problems. An attention sink can stabilize autoregressive generation over an indefinitely long stream while the model remains unable to use content that has left its recent-token cache. We argue that this distinction should be explicit in system claims and evaluation. We introduce three horizons: the stability horizon, over which predictive behavior remains well behaved; the access horizon, over which past content can still causally affect the output; and the utility horizon, over which a task retains acceptable performance. We show constructively that the stability horizon can be infinite while the access and utility horizons are finite. We then propose ThreeH, an evaluation contract that measures all three horizons under a common state and compute budget. Applying the framework to attention-sink streaming clarifies its strength, constant-memory, stable generation, without treating anchor tokens as semantic memory. The framework exposes roles for cache policies, recurrent state, retrieval, and external memory. Experiments on 128K-token streams, delayed binding recall, and delayed decisions show that attention sinks preserve local modeling but not content beyond the active cache; recurrent and retrieval state extend the semantic horizon.

## 1. 核心问题与研究动机

- **背景**：语言模型日益需要"持续运行"（数天的对话、无界事件流、超长生成），而标准稠密注意力的 KV 缓存随流长度线性增长，内存不可承受。
- **已有方案**：以滑动窗口限制内存会导致生成质量崩塌；StreamingLLM 提出保留少量初始 KV 状态作为 **attention sink（注意力汇）**，无需微调即可在数百万 token 上保持稳定生成。
- **核心问题**：这一成果常被过度解读。作者指出，"无限上下文""流式""长期记忆"三个概念被混用，导致**生成流畅但遗忘十分钟前的事实**这类系统被错误地宣称为具备记忆能力。
- **整体含义**：论文主张必须把**流稳定性**与**长期召回**显式分离，用三种可测量的"视界"替代含糊的"上下文长度"表述，从而让评测证据与能力宣称相匹配。

## 2. 方法论：三种视界 + ThreeH 评估契约

### 2.1 形式化设定
- 设 token 流 $x_{1:t}$，模型保留状态 $M_t$，有界状态更新 $M_t = U(M_{t-1}, x_t)$，且 $|M_t| \le B$。
- 预算 $B$ 必须计入**所有持久状态**（KV 向量、循环激活、压缩摘要、检索段落等），而非仅可见提示。

### 2.2 三种视界定义
- **稳定视界 $H_{stab}(\epsilon)$**：预测损失相对声明参考的超出量 $\Delta L(t) \le \epsilon$ 所能持续的最大位置 $T$。关注"模型能否继续正常运行"。
- **访问视界 $H_{access}(t)$**：改变早期 token $x_i$ 能否因果性地改变输出分布 $y_t$，即 $\max\{t-i : x_i \rightsquigarrow y_t\}$。这是状态更新与读取机制的**因果属性**；纯滑窗中非初始内容一旦被驱逐即无法影响输出。
- **效用视界 $H_{util}(\mathcal{T}, \alpha)$**：决定性信息放在查询前 $d$ 个 token 时任务得分仍 $\ge \alpha$ 的最大 $d$。它通常远小于架构上的访问视界，因为"可访问"不等于"被使用"（Lost in the Middle 现象）。

### 2.3 核心命题（构造性证明）
- **命题 1（视界分离）**：存在有界状态自回归模型，其 $H_{stab}(\epsilon) = \infty$，但非初始 token 的 $H_{access}(t) \le W$，且在延迟召回任务上 $H_{util} \le W$。
- 构造思路：模型只精确表示阶数为 $W$ 的平稳过程 → 预测损失不随流长增长；同时设置一个延迟召回任务，答案来自 $t-W-1$ 处且与中间流独立的随机符号 → 状态中不含该符号的任何函数，访问与效用被锁死在 $W$。

### 2.4 对 attention sink 的机理澄清
- 早期 token 在因果自注意力中被几乎所有后续位置看到，预训练模型会对其分配大量注意力；移除它们会改变归一化几何、使窗口化 KV 缓存失稳。
- 因此 sink 支撑两个论断：① 使计算过程足够平稳以支持长时推理；② 以恒定 KV 内存实现这一点。
- **不支持第三个论断**：初始状态编码了后续任意事件。固定初始 token 的 KV 在事件到达前就已算出且不会回溯更新，被驱逐的中间内容没有任何通往未来输出的路径。

### 2.5 ThreeH 评估契约（三条轨道 + 预算规则）
- **Track A 流稳定性**：输入远长于训练窗口的自然文本流，报告分桶预测损失、最差桶退化、每 token 延迟、峰值显存、持久状态大小；参考基线须明确（稠密注意力 / 窗口重算 / 定长预言机），拼接文档边界效应单独报告。
- **Track B 因果保持**：插入随机绑定/状态变更，按对数间隔扫描滞后 $d$，为每个目标配一个**仅改变目标值的反事实流**，只有跨对输出正确改变才算"保持"。必须覆盖：干扰（相似键多绑定）、更新（新值覆盖旧值）、位置（首/中/近）、查询延迟（写入时未来查询未知）、负例（从未出现的键）。
- **Track C 延迟任务效用**：把旧信息嵌入下游决策（执行更新后的指令、消解矛盾、延续计划），报告任务分数—滞后曲线与 $H_{util}$；查询须在状态写入时隐藏，否则压缩/检索策略会退化为"查询聚焦的上下文选择"。
- **预算报告格式**：$(B_{device}, B_{external}, F_{token}, L_{token}, L_{query})$，即设备驻留状态、外部存储状态、每流 token 摊销算力、生成长延迟、查询时检索延迟。建议发布**视界曲线**而非单一最大长度。

### 2.6 系统族诊断
- **Sink 窗口流式**：稳定视界近乎无限、设备内存恒定；一般访问视界 = 近期窗口 + 少量固定初始位置。
- **循环/压缩状态**：建立从旧内容到未来输出的因果路径，访问视界可超出可见窗口，失效模式是**有损干扰**（必须在未来查询未知时就决定保留什么）。
- **检索增强记忆**：物理访问视界可等于存储保留期，但效用视界取决于索引、查询构造、选择与下游使用。
- **混合系统**：建议模块化目标——sink 层优化稳定性，写入路径优化保持，检索+执行优化效用；单一端到端分数无法定位故障模块。

## 6. 主要结论与发现

- **稳定 ≠ 记忆**：注意力汇可在无界流上保持稳定生成与恒定内存，但普通内容一旦被驱逐就失去通往输出的路径；StreamingLLM 的 1.04× 困惑度与 25% 远端召回并存，正是"局部语言建模看起来无限稳定、语义访问仅一个窗口"的写照。
- **视界可分离且实测分离**：$H_{stab}$ 可无限而 $H_{access}$、$H_{util}$ 有限；三者各自有独立瓶颈——Window 受归一化限制、StreamingLLM 受驱逐限制、Recurrent 受干扰限制、Sink+retrieval 受选择与使用限制。
- **效用视界低于访问视界**：即使信息可被检索到，仍需被正确解释与执行，因此任务效用始终是三者中最短或最脆弱的一环。
- **设计含义**：应对"无限"一词保持克制——"有界 KV 缓存的无限时长生成"是精确且强的主张，"无限上下文"需要窗口外的保持证据，"长期记忆"还需延迟任务效用证据；不要把锚点 token 当作语义记忆。

## 7. 优点

- **概念贡献清晰且可操作**：把含糊的"上下文长度"拆成三个形式化、可测量、可比较的视界，并给出构造性分离证明，使论证从直觉上升为命题。
- **反事实评测设计严谨**：要求每个目标配对一条只改变目标值的反事实流，从根本上杜绝流畅幻觉与先验答题冒充记忆；同时要求查询在写入时未知，防止"已知答案的压缩/检索"作弊。
- **预算口径统一**：把设备状态、外部存储、摊销算力、生成长延迟、检索延迟一并纳入报告，明确区分"恒定内存流式系统"与"小型 KV + 大型向量库"的分层记忆系统。
- **诊断性框架实用**：对四类系统族分别指出其可达视界与典型失效模式（驱逐 / 干扰 / 选择与使用），并给出模块化优化建议，可直接指导长时运行 agent 的架构拆分。
- **立场克制**：明确表示目的不是贬低流式方法，而是让成就"精确化"，并承认 sink 在稳定性上的真实价值。

- **作者自陈的局限**：视界测量依赖所选流、任务族、分数阈值与参考系统；反事实流若编辑不当会变得不自然；困惑度受分词影响；外部记忆核算涉及存储基础设施的政策选择。
