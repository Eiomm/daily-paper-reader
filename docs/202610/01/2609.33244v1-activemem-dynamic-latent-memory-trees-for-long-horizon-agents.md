## 摘要
大型语言模型（LLM）智能体日益依赖外部记忆来支持长时程推理与决策。现有记忆系统通常将历史轨迹或摘要作为独立的上下文片段进行检索，忽视了多步执行所隐含的过程依赖关系。随着记忆规模扩大，这种扁平化检索会引入上下文碎片化和跨任务干扰，导致推理轨迹在结构上不一致。我们提出 ActiveMem，一种分层记忆框架，它将智能体经验递归地组织为依赖感知的潜在执行树。ActiveMem 将轨迹抽象为可复用的子任务节点，同时显式保留执行转移，从而能够以当前执行状态为条件检索连贯的推理路径。为支持持续适应，ActiveMem 进一步通过强化学习学习动态记忆扩展、检索与剪枝策略。在多种智能体基准上的实验表明，与现有基于记忆的智能体相比，ActiveMem 持续提升任务完成度、推理稳定性和记忆效率。此外，ActiveMem 使紧凑的开源权重模型能够取得与规模大得多的专有系统相竞争的性能。

## Abstract
Large Language Model (LLM) agents increasingly rely on external memory to support long-horizon reasoning and decision making. Existing memory systems typically retrieve historical trajectories or summaries as independent context fragments, overlooking the procedural dependencies underlying multi-step execution. As memory scales, such flat retrieval introduces context fragmentation and cross-task interference, leading to structurally inconsistent reasoning trajectories. We propose ActiveMem, a hierarchical memory framework that recursively organizes agent experiences into dependency-aware latent execution trees. ActiveMem abstracts trajectories into reusable subtask nodes while explicitly preserving execution transitions, enabling coherent reasoning-path retrieval conditioned on the current execution state. To support continual adaptation, ActiveMem further learns dynamic memory expansion, retrieval, and pruning policies through reinforcement learning. Experiments across various agent benchmarks demonstrate that ActiveMem consistently improves task completion, reasoning stability, and memory efficiency over existing memory-based agents. Moreover, ActiveMem enables compact open-weight models to achieve competitive performance with substantially larger proprietary systems.

## 2. 方法论

### 2.1 核心思想
- 将智能体经验组织为**分层潜在记忆树（Hierarchical Latent Memory Tree, HLMT）**：
  - **节点**编码可复用的子任务级潜在抽象（连续向量，而非原始文本块）。
  - **边**显式保留执行依赖/转移关系。
- 检索时返回**依赖一致的执行路径**而非孤立片段，实现任务隔离与因果链保留。
- 记忆拓扑本身被建模为**自适应决策过程**，通过强化学习优化扩展、检索、剪枝。

### 2.2 问题形式化
- 任务指令 x，冻结 LLM πθ 与环境 E 交互 T 步，得到轨迹 τ。
- 历史前缀被压缩为动态 HLMT，记为 Tt，按离散更新函数演化：
  - `Tt = TreeUpdate(Tt-1, a_tree_{t-1})`
- 给定当前状态 st，检索相关记忆路径 `Pt = fretrieve(st, Tt)`。
- 轻量控制器 Wϕ 处理路径 Pt 与观测编码 ht（冻结 LLM 的末 token 隐状态），得到共享表示 ut，分两路：
  - **Latent 头**：生成潜在记忆前缀 mt，条件化冻结 LLM（隐式定义新策略 πθ,ϕ(at|st) = πθ(at|st, mt(ϕ))）。
  - **Tree 头**：预测拓扑动作 a_tree_t。
- 目标：`max_ϕ E_{x~D, τ~πθ,ϕ}[R(τ)]`。

### 2.3 关键技术细节

**（1）HLMT 结构**
- 节点 `ni = (ei, pa(i), ch(i))`，ei 为节点嵌入（压缩潜在摘要），pa/ch 为父指针与子节点集。
- 上层节点捕获粗粒度任务语义，下层节点保留细粒度执行细节，支持粗到细推理。
- t=0 用虚拟根节点 nr 初始化，不编码任务语义，情节边界重置。

**（2）递归贪心检索**
- 以 ht 为查询，在每层选择与子节点余弦相似度最大者：
  - `n_{k+1} = argmax_{n∈ch(k)} (ht·en)/(||ht||·||en||)`
- 相似度低于阈值 τstop 时终止，得到激活路径 Pt。

**（3）双头记忆控制器**
- 路径经均值池化得到 p̄t，与 ht 拼接后经 2 层 MLP 得共享表示 ut。
- **Latent 注入头**：`mt = Wlatent·ut ∈ R^{lp×dmodel}`，作为动态软提示直接前置到当前观测的输入嵌入，避免逐层修改；梯度虽冻结 LLM 参数 θ，但可经 LLM 计算图回传至输入层更新 ϕ。
- **Tree 动作头**：`πtree(·|ut) = Softmax(Wtree·ut)`，采样离散拓扑动作。

**（4）即时执行（TreeUpdateImmediate）**
- `insert`：新节点 `enew = Wins·ut` 挂到检索到的叶节点 nd 下，保留时序层次。
- `update`：用门控 `α = σ(Wgate·ut)` 细化叶节点：`ed ← (1-α)ed + α·Wupd·ut`。
- 所有新插入/更新嵌入施加 **L2 归一化**，防止表示坍塌。

**（5）延迟执行（TreeMaintenance）**
- 情节结束时按环境反馈计算节点效用 S(ni)，同一情节多次激活取平均防止高频循环过度计分。
- 用指数移动平均平滑：`SEMA(ni) ← (1-β)SEMA(ni) + βS(ni)`。
- 低于阈值 τdel 的过时节点被剪枝，其子节点重挂到父节点以维持连通性。
- 兄弟节点相似度 `sim(ei,ej) > τmerge` 时通过平均池化融合。

**（6）训练配方（GRPO + 层次化优势）**
- 用 GRPO 避免维护 Critic 网络，节省显存。
- 节点效用含可验证过程奖励与最终回报：`S(ni) = Σ_{k=ti}^{T} γ^{k-ti} rk`。
- 层次化优势：
  - `Ai = λg·[(S(ni)-μG(S))/(σG(S)+ε0)] + λl·[S(ni)-S(pa(i))]`
  - 全局项鼓励任务级有用性，局部项保留节点相对专业化。
- 联合目标：`L(ϕ) = Llatent_GRPO(ϕ) + λ·Ltree_GRPO(ϕ)`，含 KL 惩罚防止策略崩溃。
- 深度感知折扣：`Ãi = γ^{di}·Ai`。

**（7）算法流程（Algorithm 1 概述）**
- 初始化 T0 → 循环每步：编码 ht → 检索 Pt → 池化 → 共享表示 ut → 生成 mt 与 a_tree_t → 冻结 LLM 生成动作 → 环境反馈 → 即时更新树 → 情节末执行 TreeMaintenance → 用轨迹优化 ϕ。

## 6. 主要结论与发现

- ActiveMem 在**全部领域**持续提升任务完成度、推理稳定性与记忆效率，在长时程交互与静态短时程推理任务上均达 SOTA。
- 相比 MemGen 等最强基线，ActiveMem-GRPO 在各骨干与数据集上全面领先（如 Qwen3-8B 上 ALFWorld 95.57%、GSM8K 94.81%）。
- **跨尺度跃迁**：紧凑开源模型（如 SmolLM3-3B、Qwen2.5-1.5B）经 ActiveMem 后接近甚至超越更大专有系统；WebShop 上 ActiveMem 超过 GPT-4o、AgentLM-13B，且 Peak Token 减少 2.8×、依赖降低 1.9×、推理加速 1.5×。
- **效率优势随任务复杂度增长**：3–16 objectives 下基线 Peak Token 近似线性增长，ActiveMem 保持低内存足迹；16-objective 时仅用 14B 基线 27.1% 峰值 token 和 29.3% 推理时间即超越之。
- **泛化性强**：抽象出的是过程逻辑而非领域词汇，跨域迁移（如 KodCode→MATH、ALFWorld→FEVER）表现稳健，避免灾难性遗忘。
- **消融验证**：HLMT 是最关键组件（去掉后 GPQA 从 54.49% 降至 44.53%，BigCodeBench 从 84.39% 降至 69.88%）；Latent Injection、层次化优势、Tree Action Head、Merge/Delete 均有正贡献。
- **理论支撑**：树检索实现无关混淆变量与动作的条件独立（互信息归零）；树规模在插入-剪枝动态平衡下期望有界 O(1)；冻结 LLM 使优化时域从 token 级降到树深度级，方差二次缩减。

## 7. 优点

- **问题定位准确**：明确指出扁平记忆的"过程依赖缺失"是长时程智能体的结构性瓶颈，并用因果图/互信息给出形式化解释。
- **方法设计新颖且系统**：
  - 用**连续潜在节点**替代原始文本块，避免上下文膨胀。
  - **树结构 + 任务隔离**显式保留因果链、抑制跨任务干扰。
  - **双头解耦控制器**同时完成"记忆注入"与"拓扑演化"，且冻结主干 LLM，训练开销低。
  - **即时执行 + 延迟维护**分离高频语义更新与低频效用剪枝，避免解码期结构抖动。
- **训练策略合理**：GRPO 免 Critic、组内归一化稳定长轨迹稀疏奖励；引入可验证过程监督与**层次化优势**（全局+局部），解决长时程信用分配。
- **效率与效果兼顾**：检索复杂度 O(D·B) ≈ O(log_B|T|)，远优于扁平检索的 O(|T|)；实验证明 token 与延迟显著下降。
- **实验覆盖面广**：交互式与推理式、单目标与多目标、静态与长时程、开源与专有基线均有涉及，并附理论证明与复杂度分析。
- **可复现性较好**：附录给出详细超参、prompt 模板、RAG 配置与指标定义。

## 8. 不足与局限

- **对隐状态访问的依赖**：方法需要从冻结 LLM 提取末 token 隐状态并注入潜在前缀，要求对模型内部激活的访问与修改能力，**难以直接用于纯 API 黑盒模型**，限制了部署场景。
